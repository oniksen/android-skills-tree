## 1. Переменные {#peremennye}

Переменные позволяют хранить данные, обращаться к ним по имени и использовать в вычислениях. Практически любая программа работает с данными: получает их от пользователя, преобразует, сохраняет и передаёт другим частям приложения.

В Kotlin переменные объявляются с помощью `val` и `var`. Разница между ними определяет, можно ли присвоить переменной новое значение после первоначального объявления.

:::cards
- **Имя** — Понятное имя описывает назначение переменной: `userName`, а не `x`.
- **Значение** — Значение можно вычислить, получить от пользователя, прочитать из ресурса или передать в функцию.
- **Изменяемость** — Нужно заранее решить, можно ли менять значение после создания переменной.
- **Тип** — Kotlin знает тип переменной: число, строка, булево значение, список, объект и другие.
:::

> **Ключевая идея:** выбирайте `val` по умолчанию. Переходите на `var` только тогда, когда значение действительно должно меняться.

### 1.1. `val` и `var` {#val-i-var}

#### `val` — переменная только для чтения

`val` (от *value*) объявляет переменную, которой можно присвоить значение только один раз.

```kotlin
val name = "Alex"
val age = 25

println(name)
println(age)

// Ошибка компиляции:
// name = "John"
```

После первоначального присваивания нельзя заменить значение, на которое ссылается `val`.

#### `var` — изменяемая переменная

`var` (от *variable*) объявляет переменную, значение которой можно менять.

```kotlin
var age = 25

println(age) // 25

age = 26

println(age) // 26
```

Тип переменной при этом остаётся тем же. Если переменная изначально имеет тип `Int`, присвоить ей `String` нельзя:

```kotlin
var age = 25

// Ошибка компиляции:
// age = "Twenty five"
```

#### Важное различие: неизменяемая ссылка и неизменяемый объект

`val` запрещает повторное присваивание самой переменной, но не гарантирует неизменность объекта, на который она ссылается.

| Ключевое слово | Можно переприсвоить? | Когда использовать |
| --- | --- | --- |
| `val` | Нет | Большинство значений, результаты вычислений, параметры функций, свойства без изменения. |
| `var` | Да | Счётчики, накопление результата, состояние, которое действительно меняется. |

> [!WARNING]
> **Частая ошибка:** думать, что `val` делает объект неизменяемым. `val` фиксирует только ссылку; содержимое изменяемого объекта всё ещё можно менять.

```kotlin
val names = mutableListOf("Alex", "Maria")

// Разрешено: изменяется содержимое списка.
names.add("John")

println(names) // [Alex, Maria, John]

// Ошибка компиляции: нельзя заменить ссылку.
// names = mutableListOf("Peter")
```

Здесь `names` нельзя переназначить, но сам список остаётся изменяемым.

Для обычных переменных рекомендуется использовать `val`, если новое присваивание не требуется. Это уменьшает количество возможных изменений состояния программы и делает код предсказуемее.

```kotlin
// Предпочтительно, если значение не меняется.
val userName = "Alex"

// Используется var, потому что значение изменяется.
var counter = 0
counter++
```

### 1.2. Объявление и инициализация {#obyavlenie-i-initsializatsiya}

Объявление переменной — это создание переменной с определённым именем и типом.

Инициализация — присваивание ей первоначального значения.

```kotlin
val name: String = "Alex"
```

Здесь:

- `val` — способ объявления;
- `name` — имя переменной;
- `String` — тип;
- `"Alex"` — первоначальное значение.

Тип можно не указывать, если компилятор способен определить его самостоятельно:

```kotlin
val name = "Alex"       // String
val age = 25            // Int
val price = 19.99       // Double
val isActive = true     // Boolean
```

Это называется **выведением типа** (*type inference*).

Компилятор анализирует значение справа от `=` и определяет тип переменной.

При необходимости тип можно указать явно:

```kotlin
val age: Int = 25
val price: Double = 19.99
```

#### Отложенная инициализация локальной переменной

Локальную переменную можно объявить без значения, если компилятор может доказать, что она будет инициализирована до первого использования.

```kotlin
fun getUserName(isAuthorized: Boolean): String {
    val name: String

    if (isAuthorized) {
        name = "Alex"
    } else {
        name = "Guest"
    }

    return name
}
```

В данном случае оба возможных пути выполнения присваивают значение `name`.

Но следующий пример некорректен:

```kotlin
fun getUserName(isAuthorized: Boolean): String {
    val name: String

    if (isAuthorized) {
        name = "Alex"
    }

    // Ошибка: компилятор не может гарантировать,
    // что name была инициализирована.
    return name
}
```

Компилятор Kotlin проверяет, что переменная не используется до инициализации.

#### Объявление переменной и значение `null`

В Kotlin обычная переменная не может содержать `null`, если её тип явно не объявлен nullable.

```kotlin
val name: String = "Alex"

// Ошибка компиляции:
// name = null
```

Чтобы разрешить отсутствие значения, используется знак `?`:

```kotlin
var name: String? = "Alex"

name = null
```

Подробнее nullable-типы рассматриваются в разделе «Обработка ошибок».

### 1.3. Константы `const val` {#konstanty-const-val}

Для значений, которые известны уже во время компиляции и не должны изменяться, Kotlin предоставляет `const val`.

```kotlin
const val MAX_LOGIN_ATTEMPTS = 3
const val APP_NAME = "Study Platform"
const val DEFAULT_TIMEOUT_SECONDS = 30
```

Обычный `val` обозначает ссылку только для чтения. `const val` дополнительно сообщает компилятору, что значение является compile-time constant — константой времени компиляции.

#### Где разрешено объявлять `const val`

Константы можно объявлять:

1. На уровне файла.
2. Внутри `object`.
3. Внутри `companion object`.

```kotlin
const val DEFAULT_PAGE_SIZE = 20

object AppConfig {
    const val API_VERSION = "v1"
}

class UserRepository {
    companion object {
        const val MAX_USERS = 100
    }
}
```

#### Ограничения

Значение `const val` должно быть доступно на этапе компиляции. Поддерживаются значения типа `String` и примитивные типы.

Нельзя использовать результат выполнения произвольной функции:

```kotlin
// Ошибка: функция не является compile-time constant.
fun getDefaultName() = "Guest"

// const val DEFAULT_NAME = getDefaultName()
```

Также нельзя объявить `const val` внутри обычной функции:

```kotlin
fun calculate() {
    // Ошибка.
    // const val MAX_VALUE = 100
}
```

#### Разница между `val` и `const val`

```kotlin
val currentTime = System.currentTimeMillis()

const val MAX_RETRIES = 3
```

`currentTime` вычисляется во время выполнения программы.

`MAX_RETRIES` известно компилятору заранее.

Используй `const val` для настоящих констант: фиксированных ключей, названий, числовых ограничений и других compile-time значений.

### 1.4. Область видимости переменных {#oblast-vidimosti-peremennyh}

Область видимости (*scope*) определяет, из какой части программы можно обратиться к переменной.

#### Локальные переменные

Переменные, объявленные внутри функции, доступны только внутри этой функции и вложенных в неё блоков.

```kotlin
fun calculate() {
    val result = 10 + 20

    println(result)

    if (result > 15) {
        val message = "Большое значение"
        println(message)
    }

    // Ошибка: message объявлена внутри if.
    // println(message)
}
```

После завершения блока переменная перестаёт быть доступной по имени из внешнего кода.

#### Область видимости внутри вложенных блоков

Внутренний блок может обращаться к переменным внешнего блока.

```kotlin
fun main() {
    val userName = "Alex"

    if (userName.isNotEmpty()) {
        val greeting = "Привет, $userName"
        println(greeting)
    }
}
```

Но внешний блок не имеет доступа к переменным, объявленным внутри вложенного блока.

#### Переменные уровня файла

Переменные можно объявлять непосредственно в `.kt`-файле, вне функций и классов.

```kotlin
val appName = "Study Platform"

var launchCount = 0

fun launchApp() {
    launchCount++
    println("Запуск $appName №$launchCount")
}
```

Такие объявления доступны другим декларациям в пределах соответствующей области видимости и с учётом модификаторов доступа.

#### Свойства класса

Переменные, объявленные внутри класса, называются свойствами (*properties*).

```kotlin
class User {
    val name = "Alex"
    var age = 25

    fun printInfo() {
        println("$name, $age")
    }
}
```

Обращение к свойствам объекта выполняется через точку:

```kotlin
val user = User()

println(user.name)
println(user.age)
```

У каждого экземпляра класса собственные свойства экземпляра, если только речь не идёт о членах `object` или `companion object`.

#### Область видимости и модификаторы доступа

Не путай область видимости с модификаторами доступа.

Область видимости отвечает на вопрос, где существует имя переменной в лексической структуре кода.

Модификатор доступа определяет, какие части программы могут обращаться к декларации.

Основные модификаторы Kotlin:

| Модификатор | Доступность |
|---|---|
| `public` | Доступен отовсюду, где виден содержащий тип или модуль |
| `private` | Для члена класса — внутри класса; для top-level объявления — внутри файла |
| `protected` | Внутри класса и его наследников |
| `internal` | В пределах одного модуля |

По умолчанию используется `public`.

```kotlin
class User {
    private val password = "secret"

    fun checkPassword(candidate: String): Boolean {
        return password == candidate
    }
}
```

Внешний код не может напрямую прочитать `password`, но может воспользоваться публичным методом `checkPassword`.

### 1.5. Правила именования {#pravila-imenovaniya}

Правильные имена помогают понимать код без дополнительных комментариев.

В Kotlin принято использовать `camelCase` для функций, свойств и локальных переменных:

```kotlin
val userName = "Alex"
var currentPage = 1

fun loadUserData() {
    // ...
}
```

Названия классов и объектов используют `PascalCase`:

```kotlin
class UserRepository

class PaymentProcessor

object DatabaseConfig
```

Константы обычно пишутся в `UPPER_SNAKE_CASE`:

```kotlin
const val MAX_RETRY_COUNT = 5
const val API_BASE_URL = "https://example.com"
```

#### Рекомендации

- Используй понятные имена, отражающие назначение сущности.
- Избегай одиночных букв, кроме коротких локальных циклов, индексов и математических выражений.
- Не используй транслитерацию вместо английских названий.
- Не добавляй тип в имя переменной без необходимости.
- Для функций выбирай глагол или глагольную конструкцию.
- Для классов — существительное или название сущности.

Плохо:

```kotlin
val x = 25
val s = "Alex"

fun doIt() {
    // ...
}
```

Лучше:

```kotlin
val userAge = 25
val userName = "Alex"

fun loadUserProfile() {
    // ...
}
```

Для Boolean-свойств часто используют формы `is`, `has`, `can`:

```kotlin
val isAuthorized = true
val hasInternetConnection = false
val canEditProfile = true
```

### 1.6. `lateinit` и `lazy` {#lateinit-i-lazy}

Иногда значение нельзя или нежелательно создавать непосредственно в момент объявления свойства.

В Kotlin есть два распространённых механизма отложенной инициализации:

- `lateinit` — свойство будет инициализировано позднее вручную;
- `lazy` — значение будет вычислено автоматически при первом обращении.

#### `lateinit`

`lateinit` используется для отложенной инициализации изменяемого свойства.

```kotlin
class UserScreen {
    lateinit var title: String

    fun initialize() {
        title = "Профиль пользователя"
    }

    fun showTitle() {
        println(title)
    }
}
```

Использование:

```kotlin
val screen = UserScreen()

screen.initialize()
screen.showTitle()
```

Главная особенность: до первого обращения к свойству его необходимо инициализировать.

Если попытаться прочитать неинициализированное свойство, произойдёт `UninitializedPropertyAccessException`.

```kotlin
class UserScreen {
    lateinit var title: String
}

val screen = UserScreen()

// Ошибка во время выполнения:
// println(screen.title)
```

Ограничения `lateinit`:

- Свойство должно быть объявлено через `var`.
- Тип должен быть non-nullable.
- Нельзя использовать примитивные типы вроде `Int`, `Boolean` и `Double`.
- Нельзя использовать `lateinit` для свойства с пользовательским getter или setter.
- Свойство нельзя объявить `lateinit` непосредственно в параметрах первичного конструктора.

Проверить, было ли свойство инициализировано, можно через `isInitialized`:

```kotlin
class UserScreen {
    lateinit var title: String

    fun printTitle() {
        if (::title.isInitialized) {
            println(title)
        } else {
            println("Заголовок ещё не установлен")
        }
    }
}
```

`lateinit` подходит для случаев, когда объект должен получить значение извне после создания.

Например, это встречается в Android-коде при инициализации View Binding, когда поле заполняется после создания представления.

Однако не следует использовать `lateinit` просто для того, чтобы избежать нормальной инициализации в конструкторе.

#### `lazy`

`lazy` используется для вычисления значения только при первом обращении к свойству.

```kotlin
class Report {
    val content: String by lazy {
        println("Формируем содержимое отчёта")
        loadReport()
    }

    private fun loadReport(): String {
        return "Отчёт готов"
    }
}
```

Использование:

```kotlin
val report = Report()

// Здесь loadReport() ещё не вызывается.

println(report.content)

// Здесь значение вычисляется впервые.
println(report.content)

// При повторном обращении используется уже вычисленное значение.
```

Результат вычисления сохраняется. Блок `lazy` выполняется один раз для данного свойства.

Особенности:

- `lazy` используется со свойством `val`.
- Инициализация выполняется при первом чтении.
- Результат вычисления кэшируется.
- По умолчанию используется потокобезопасный режим `LazyThreadSafetyMode.SYNCHRONIZED`.

Можно явно задать режим:

```kotlin
val value by lazy(LazyThreadSafetyMode.NONE) {
    calculateValue()
}
```

Основные режимы:

| Режим | Поведение |
|---|---|
| `SYNCHRONIZED` | Потокобезопасная инициализация, используется по умолчанию |
| `PUBLICATION` | При конкурентном первом доступе блок может выполниться несколько раз, но будет опубликовано одно значение |
| `NONE` | Без синхронизации; использовать только при гарантированном отсутствии конкурентного доступа |

#### `lateinit` или `lazy`?

| Критерий | `lateinit` | `lazy` |
|---|---|---|
| Тип свойства | `var` | `val` |
| Кто задаёт значение | Внешний код | Блок инициализации |
| Когда инициализируется | При явном присваивании | При первом чтении |
| Повторная установка | Возможна | Нет |
| Возможность ошибки при чтении до инициализации | Да | Нет, блок выполнится автоматически |
| Примитивные типы | Не поддерживаются | Поддерживаются |

Простой способ запомнить:

- `lateinit`: «Я установлю значение позже».
- `lazy`: «Вычисли значение, когда оно действительно понадобится».

### Практика: Переменные

1. Создай переменную `userName` через `val` и выведи её в консоль.
2. Создай `var counter`, увеличь его несколько раз и выведи результат.
3. Объяви `const val` для максимального количества попыток авторизации.
4. Создай функцию с локальной переменной и попробуй обратиться к ней за пределами функции.
5. Создай класс `User` со свойствами `name` и `age`.
6. Создай класс, в котором одно свойство инициализируется через `lateinit`, а другое — через `lazy`.
7. Объясни, почему список, объявленный через `val`, всё ещё может изменяться.

## 2. Типы данных {#tipy-dannyh}

Тип данных определяет, какие значения может хранить переменная и какие операции можно над ними выполнять.

Kotlin — статически типизированный язык. Это означает, что типы переменных и выражений проверяются компилятором.

Например, нельзя без преобразования присвоить строку переменной типа `Int`.

> **Ключевая идея:** тип — это контракт значения. Компилятор проверяет его до запуска программы и помогает избежать ошибок.

```kotlin
val age: Int = 25

// Ошибка компиляции:
// val name: String = age
```

Система типов помогает обнаруживать большое количество ошибок ещё до запуска программы.

### 2.1. Числовые типы {#chislovye-tipy}

Kotlin предоставляет несколько типов для работы с числами.

| Тип | Размер | Назначение |
|---|---:|---|
| `Byte` | 8 бит | Небольшие целые числа |
| `Short` | 16 бит | Целые числа |
| `Int` | 32 бита | Основной целочисленный тип |
| `Long` | 64 бита | Большие целые числа |
| `Float` | 32 бита | Числа с плавающей точкой |
| `Double` | 64 бита | Числа с плавающей точкой повышенной точности |

> **Практический совет:** по умолчанию используйте `Int` и `Double`. Более узкие типы выбирайте только при реальных ограничениях памяти или совместимости.

#### Целочисленные типы

`Int` чаще всего используется для обычных целых чисел:

```kotlin
val age: Int = 25
val temperature: Int = -10
val numberOfAttempts: Int = 3
```

Диапазоны:

| Тип | Диапазон |
|---|---|
| `Byte` | от -128 до 127 |
| `Short` | от -32 768 до 32 767 |
| `Int` | от -2 147 483 648 до 2 147 483 647 |
| `Long` | от -2⁶³ до 2⁶³ - 1 |

Для больших значений используется `Long`:

```kotlin
val population: Long = 8_000_000_000L
```

Суффикс `L` указывает, что числовой литерал имеет тип `Long`.

Для удобства чтения больших чисел Kotlin поддерживает подчёркивания:

```kotlin
val oneMillion = 1_000_000
val longNumber = 9_876_543_210L
```

Подчёркивания не влияют на значение числа.

#### Числа с плавающей точкой

Для дробных чисел обычно используют `Double`:

```kotlin
val price = 19.99
val averageScore = 87.5
```

По умолчанию дробные числовые литералы имеют тип `Double`.

Если нужен `Float`, используется суффикс `f` или `F`:

```kotlin
val weight: Float = 72.5f
val height: Double = 1.82
```

`Double` имеет большую точность, чем `Float`.

#### Особенности вычислений с плавающей точкой

Числа с плавающей точкой не всегда могут быть представлены в двоичной системе счисления точно.

```kotlin
val result = 0.1 + 0.2

println(result)
```

Результат может отличаться от математически ожидаемого `0.3` на очень небольшую величину.

Поэтому сравнивать дробные числа через точное равенство не всегда безопасно:

```kotlin
val a = 0.1 + 0.2
val b = 0.3

println(a == b) // Не следует полагаться на true.
```

Для задач с деньгами обычно используют целые значения в минимальных денежных единицах или специализированные decimal-типы, например `BigDecimal` на JVM.

#### Тип `Number`

`Number` — общий базовый тип для числовых типов Kotlin.

```kotlin
fun printNumber(number: Number) {
    println(number)
}

printNumber(10)
printNumber(10.5)
printNumber(100L)
```

Он позволяет передавать в функцию значения разных числовых типов.

Однако `Number` не означает, что с любым числом можно выполнять все операции без преобразований. При необходимости конкретный тип можно получить через `toInt()`, `toDouble()` и другие функции.

### 2.2. `Char` и `Boolean` {#char-i-boolean}

#### `Char`

`Char` предназначен для хранения одного символа.

```kotlin
val letter: Char = 'A'
val digit: Char = '7'
val symbol: Char = '#'
```

Для символов используются одинарные кавычки.

```kotlin
val firstLetter = 'K'
```

Строка, напротив, записывается в двойных кавычках:

```kotlin
val text = "Kotlin"
```

`Char` поддерживает управляющие символы:

```kotlin
val newLine = '\n'
val tab = '\t'
val quote = '\''
val backslash = '\\'
```

Также можно использовать Unicode-последовательности:

```kotlin
val copyright = '\u00A9'
println(copyright) // ©
```

Важно понимать, что `Char` в Kotlin представляет UTF-16 code unit. Не каждый визуально воспринимаемый символ Unicode укладывается в один `Char`: например, некоторые эмодзи состоят из нескольких кодовых единиц.

#### `Boolean`

`Boolean` хранит одно из двух логических значений:

- `true`;
- `false`.

```kotlin
val isAuthorized: Boolean = true
val hasInternetConnection = false
```

Чаще всего `Boolean` используется в условиях:

```kotlin
val age = 20
val isAdult = age >= 18

if (isAdult) {
    println("Доступ разрешён")
}
```

Логические значения также являются результатами сравнений:

```kotlin
val first = 10 > 5       // true
val second = 10 == 5     // false
val third = 10 != 5      // true
```

### 2.3. `String` и шаблонные строки {#string-i-shablonnye-stroki}

`String` — тип для хранения последовательности символов.

```kotlin
val language = "Kotlin"
val message = "Hello, world!"
val emptyText = ""
```

Строки в Kotlin неизменяемые (*immutable*). Это означает, что нельзя изменить отдельный символ существующей строки.

```kotlin
val language = "Kotlin"

// Ошибка:
// language[0] = 'J'
```

Но можно создать новую строку:

```kotlin
val language = "Kotlin"
val newLanguage = "J" + language.substring(1)

println(newLanguage) // Jotlin
```

#### Доступ к символам

```kotlin
val language = "Kotlin"

println(language[0]) // K
println(language[1]) // o
println(language.length) // 6
```

Индексация начинается с нуля.

Попытка обратиться к индексу, которого нет, приводит к ошибке выполнения.

```kotlin
val text = "Kotlin"

// Ошибка: индекс 10 выходит за границы строки.
// println(text[10])
```

#### Шаблонные строки

Kotlin позволяет вставлять значения переменных непосредственно в строку.

Для этого используется символ `$`:

```kotlin
val name = "Alex"
val age = 25

val message = "Меня зовут $name, мне $age лет"

println(message)
```

Если нужно вставить выражение, используется `${}`:

```kotlin
val firstName = "Alex"
val lastName = "Smith"

val fullName = "$firstName $lastName"
val length = "Имя: ${fullName.length}"

println(length)
```

Шаблоны строк удобнее и безопаснее, чем ручная конкатенация большого количества значений.

#### Многострочные строки

Для многострочных строк используются тройные двойные кавычки:

```kotlin
val message = """
    Привет!
    Это многострочная строка.
    Она сохраняет переносы строк.
""".trimIndent()

println(message)
```

`trimIndent()` удаляет общий отступ в начале строк.

Также часто используется `trimMargin()`:

```kotlin
val json = """
    |{
    |  "name": "Alex",
    |  "age": 25
    |}
""".trimMargin()
```

#### Сравнение строк

В Kotlin оператор `==` проверяет структурное равенство, то есть одинаково ли содержимое строк.

```kotlin
val first = "Kotlin"
val second = "Kot" + "lin"

println(first == second) // true
```

Оператор `===` проверяет, являются ли две ссылки ссылками на один и тот же объект.

Для сравнения содержимого строк обычно используй `==`.

### 2.4. `Array` и специализированные массивы {#array-i-spetsializirovannye-massivy}

Массив — структура данных, которая хранит фиксированное количество элементов одного типа.

#### Создание массива

```kotlin
val names = arrayOf("Alex", "Maria", "John")
```

Тип будет выведен автоматически:

```kotlin
val numbers = arrayOf(1, 2, 3)
```

Также тип можно указать явно:

```kotlin
val numbers: Array<Int> = arrayOf(1, 2, 3)
```

#### Доступ по индексу

```kotlin
val names = arrayOf("Alex", "Maria", "John")

println(names[0]) // Alex
println(names[1]) // Maria
println(names[2]) // John
```

Изменение элемента:

```kotlin
val names = arrayOf("Alex", "Maria")

names[0] = "Peter"

println(names[0]) // Peter
```

Размер массива после создания изменить нельзя:

```kotlin
val numbers = arrayOf(1, 2, 3)

// Нельзя добавить четвёртый элемент непосредственно.
// Размер массива фиксирован.
```

#### Размер и обход

```kotlin
val numbers = arrayOf(10, 20, 30)

println(numbers.size) // 3

for (number in numbers) {
    println(number)
}
```

#### Специализированные массивы

Kotlin предоставляет массивы для примитивных типов:

| Тип массива | Элементы |
|---|---|
| `ByteArray` | `Byte` |
| `ShortArray` | `Short` |
| `IntArray` | `Int` |
| `LongArray` | `Long` |
| `FloatArray` | `Float` |
| `DoubleArray` | `Double` |
| `BooleanArray` | `Boolean` |
| `CharArray` | `Char` |

Пример:

```kotlin
val numbers = intArrayOf(10, 20, 30)
val flags = booleanArrayOf(true, false, true)
val letters = charArrayOf('A', 'B', 'C')
```

Массив можно создать и через конструктор:

```kotlin
val numbers = IntArray(5)

println(numbers.joinToString()) // 0, 0, 0, 0, 0
```

Можно передать функцию инициализации:

```kotlin
val squares = IntArray(5) { index ->
    index * index
}

println(squares.joinToString()) // 0, 1, 4, 9, 16
```

`Array<Int>` и `IntArray` — не одно и то же.

`IntArray` предназначен для хранения целочисленных значений без упаковки каждого элемента в отдельный объект на JVM.

#### Когда использовать массивы

Массивы полезны, когда:

- требуется фиксированное количество элементов;
- необходимо взаимодействовать с Java API или низкоуровневым API платформы;
- важны особенности представления данных в памяти;
- реализуется собственная структура данных.

Для большинства обычных задач Kotlin предпочтительнее коллекции `List`, `Set` и `Map`.

### 2.5. Выведение типа (Type inference) {#vyvedenie-tipa-type-inference}

Type inference — механизм, при котором компилятор самостоятельно определяет тип переменной или выражения.

```kotlin
val name = "Alex" // String
val age = 25      // Int
val price = 19.99 // Double
```

Компилятор анализирует выражение, присвоенное переменной.

Можно использовать type inference и при создании коллекций:

```kotlin
val names = listOf("Alex", "Maria")
// List<String>

val numbers = listOf(1, 2, 3)
// List<Int>
```

Если тип неочевиден или требуется более конкретный контракт, его можно задать явно:

```kotlin
val userCount: Int = 100
val names: List<String> = listOf("Alex", "Maria")
```

#### Когда стоит писать тип явно

Явное указание типа полезно:

- при объявлении публичных API;
- когда выражение имеет сложный тип;
- когда нужно явно зафиксировать ожидаемый контракт;
- когда тип не выводится из начального значения.

Пример:

```kotlin
val result: Number = 10
```

Хотя справа находится `Int`, переменная объявлена как `Number`.

Это влияет на то, какие операции можно выполнять с ней непосредственно.

### 2.6. Явное преобразование типов {#yavnoe-preobrazovanie-tipov}

Kotlin не выполняет автоматическое преобразование числовых типов между собой.

```kotlin
val number: Int = 10

// Ошибка:
// val decimal: Double = number
```

Для преобразования используются функции:

```kotlin
val number: Int = 10

val longNumber: Long = number.toLong()
val doubleNumber: Double = number.toDouble()
val floatNumber: Float = number.toFloat()
```

Основные преобразования:

- `toByte()`
- `toShort()`
- `toInt()`
- `toLong()`
- `toFloat()`
- `toDouble()`

#### Потеря данных при преобразовании

Преобразование чисел не всегда сохраняет исходное значение.

```kotlin
val price = 19.99
val wholePart = price.toInt()

println(wholePart) // 19
```

При преобразовании числа с плавающей точкой в целое дробная часть отбрасывается, а не округляется.

Если нужно округление, используй соответствующие математические функции, например `roundToInt()`.

#### Преобразование строки в число

```kotlin
val text = "123"

val number = text.toInt()

println(number + 10) // 133
```

Если строка содержит некорректное число, `toInt()` выбросит `NumberFormatException`.

```kotlin
// Вызовет исключение:
// val number = "hello".toInt()
```

Для безопасного преобразования существует `toIntOrNull()`:

```kotlin
val first = "123".toIntOrNull()
val second = "hello".toIntOrNull()

println(first)  // 123
println(second) // null
```

Это позволяет обработать некорректный ввод без исключения.

### 2.7. `Unit`, `Any` и `Nothing` {#unit-any-i-nothing}

Эти типы встречаются во многих частях Kotlin и важны для понимания системы типов языка.

#### `Unit`

`Unit` обозначает отсутствие полезного возвращаемого значения.

Например, функция, которая только выводит текст:

```kotlin
fun printMessage(message: String) {
    println(message)
}
```

Если возвращаемый тип не указан, функция в данном случае возвращает `Unit`.

Можно написать это явно:

```kotlin
fun printMessage(message: String): Unit {
    println(message)
}
```

Но обычно `: Unit` не указывают.

У `Unit` существует ровно одно значение — `Unit`.

В отличие от `void` в некоторых других языках, `Unit` является настоящим типом Kotlin.

#### `Any`

`Any` — общий супертип всех non-nullable типов Kotlin.

```kotlin
val first: Any = "Kotlin"
val second: Any = 100
val third: Any = true
```

Переменная типа `Any` может хранить значения разных типов.

Но при обращении к такой переменной доступны только операции, определённые для `Any`, например:

```kotlin
val value: Any = "Kotlin"

println(value.toString())
println(value.hashCode())
println(value.equals("Kotlin"))
```

Чтобы использовать свойства конкретного типа, нужно проверить или преобразовать тип.

```kotlin
val value: Any = "Kotlin"

if (value is String) {
    println(value.length)
}
```

`Any?` — nullable-версия, которая дополнительно позволяет хранить `null`.

#### `Nothing`

`Nothing` — специальный тип, который обозначает отсутствие нормального результата.

Функция, возвращающая `Nothing`, никогда не возвращает управление обычным образом.

Например:

```kotlin
fun fail(message: String): Nothing {
    throw IllegalStateException(message)
}
```

Такая функция всегда выбрасывает исключение.

Ещё пример:

```kotlin
fun infiniteLoop(): Nothing {
    while (true) {
        // Бесконечный цикл.
    }
}
```

`Nothing` является подтипом любого другого типа. Поэтому его можно использовать в выражениях там, где ожидается другое значение.

```kotlin
fun getUserName(name: String?): String {
    return name ?: throw IllegalArgumentException("Имя не задано")
}
```

Здесь правая часть Elvis-оператора имеет тип `Nothing`, потому что при её выполнении обычного результата не будет: функция завершится исключением.

#### Сравнение

| Тип | Назначение | Пример |
|---|---|---|
| `Unit` | Нет полезного возвращаемого значения | Функция логирования |
| `Any` | Общий тип для всех non-nullable типов | Переменная для значения неизвестного типа |
| `Nothing` | Функция не возвращает нормальный результат | Выброс исключения |

### Практика: Типы данных

1. Создай переменные всех числовых типов и выведи их значения.
2. Объясни разницу между `Float` и `Double`.
3. Создай строку с именем и возрастом, используя шаблонную строку.
4. Создай массив из пяти целых чисел и выведи каждый элемент.
5. Создай `IntArray` из пяти элементов, где каждый элемент равен квадрату своего индекса.
6. Преобразуй строку `"250"` в число.
7. Попробуй безопасно преобразовать строку `"abc"` в число.
8. Создай функцию, возвращающую `Unit`.
9. Создай переменную типа `Any` и сохрани в неё сначала строку, затем число в отдельных объявлениях.
10. Объясни, почему функция, которая всегда выбрасывает исключение, может иметь возвращаемый тип `Nothing`.

## 3. Условные конструкции {#uslovnye-konstruktsii}

Условные конструкции позволяют программе выбирать разные действия в зависимости от текущих данных.

Например, приложение может:

- разрешить авторизацию, если пароль корректен;
- показать сообщение об ошибке, если данные неверны;
- выбрать скидку в зависимости от суммы покупки;
- определить статус пользователя;
- выполнить действие только при наличии необходимых условий.

В Kotlin основные конструкции ветвления — `if` и `when`.

> **Ключевая идея:** условие должно быть булевым выражением. Если логика ветвления становится сложной, разбивайте её на функции и понятные переменные.

### 3.1. `if / else` {#if-else}

`if` проверяет условие и выполняет блок кода, если условие истинно.

```kotlin
val age = 20

if (age >= 18) {
    println("Совершеннолетний")
}
```

Если условие ложно, блок пропускается.

Для альтернативной ветви используется `else`:

```kotlin
val age = 16

if (age >= 18) {
    println("Совершеннолетний")
} else {
    println("Несовершеннолетний")
}
```

Для нескольких условий используется `else if`:

```kotlin
val score = 75

if (score >= 90) {
    println("Отлично")
} else if (score >= 70) {
    println("Хорошо")
} else if (score >= 50) {
    println("Удовлетворительно")
} else {
    println("Неудовлетворительно")
}
```

Условия проверяются сверху вниз.

Выполнится только первая ветвь, условие которой оказалось истинным.

Поэтому порядок проверок имеет значение.

Неправильный порядок:

```kotlin
val age = 25

if (age >= 18) {
    println("Взрослый")
} else if (age >= 21) {
    println("Старше 21 года")
}
```

Вторая ветвь никогда не выполнится для возраста от 21 года и выше, потому что первая проверка уже охватывает все значения от 18.

Правильно:

```kotlin
if (age >= 21) {
    println("Старше 21 года")
} else if (age >= 18) {
    println("Взрослый")
} else {
    println("Несовершеннолетний")
}
```

### 3.2. `if` как выражение {#if-kak-vyrazhenie}

В Kotlin `if` может не только управлять выполнением кода, но и возвращать значение.

Это называется использованием `if` как выражения (*expression*).

```kotlin
val age = 20

val status = if (age >= 18) {
    "Взрослый"
} else {
    "Несовершеннолетний"
}

println(status)
```

В таком случае результатом `if` является значение последнего выражения выполненной ветви.

Можно использовать более короткую форму:

```kotlin
val max = if (10 > 20) 10 else 20
```

В Kotlin нет отдельного тернарного оператора `condition ? first : second`, как в Java или C.

Его роль выполняет `if` как выражение.

#### Тип результата

Обе ветви должны возвращать совместимые типы.

```kotlin
val result = if (true) {
    10
} else {
    20
}
```

В данном случае `result` имеет тип `Int`.

Следующий пример не будет работать как ожидается:

```kotlin
// Ошибка: if должен иметь значение,
// но ветвь else отсутствует.
val result = if (true) {
    10
}
```

Если `if` используется как выражение, обязательно должна быть ветвь `else`.

### 3.3. `when` как выражение {#when-kak-vyrazhenie}

`when` — более гибкая конструкция ветвления.

Она позволяет сравнить значение с несколькими вариантами.

```kotlin
val day = 3

val dayName = when (day) {
    1 -> "Понедельник"
    2 -> "Вторник"
    3 -> "Среда"
    4 -> "Четверг"
    5 -> "Пятница"
    6 -> "Суббота"
    7 -> "Воскресенье"
    else -> "Неизвестный день"
}

println(dayName)
```

`when` проверяет варианты по порядку и выполняет первую подходящую ветвь.

#### Несколько значений в одной ветви

Для объединения вариантов используется запятая:

```kotlin
val day = 6

val dayType = when (day) {
    1, 2, 3, 4, 5 -> "Рабочий день"
    6, 7 -> "Выходной"
    else -> "Неизвестный день"
}
```

#### Использование `when` с перечислениями

`when` особенно удобен при работе с `enum`:

```kotlin
enum class OrderStatus {
    NEW,
    PROCESSING,
    COMPLETED,
    CANCELLED
}

fun getStatusText(status: OrderStatus): String {
    return when (status) {
        OrderStatus.NEW -> "Новый заказ"
        OrderStatus.PROCESSING -> "В обработке"
        OrderStatus.COMPLETED -> "Завершён"
        OrderStatus.CANCELLED -> "Отменён"
    }
}
```

Здесь `else` не требуется, потому что обработаны все варианты перечисления.

Это называется **exhaustive when** — исчерпывающая проверка всех возможных вариантов.

Если добавить новый элемент в `enum`, компилятор напомнит, что его необходимо обработать.

### 3.4. `when` с произвольными условиями {#when-s-proizvolnymi-usloviyami}

`when` можно использовать без аргумента.

Тогда каждая ветвь содержит произвольное логическое условие.

```kotlin
val temperature = 25

val message = when {
    temperature < 0 -> "Мороз"
    temperature < 15 -> "Холодно"
    temperature < 25 -> "Тепло"
    temperature < 35 -> "Жарко"
    else -> "Очень жарко"
}

println(message)
```

Это похоже на цепочку `if / else if`, но часто позволяет записать логику компактнее.

Обрати внимание: ветви проверяются последовательно, поэтому порядок условий важен.

#### Проверка типов через `is`

В `when` можно проверять тип значения:

```kotlin
fun describe(value: Any): String {
    return when (value) {
        is String -> "Это строка длиной ${value.length}"
        is Int -> "Это целое число"
        is Boolean -> "Это логическое значение"
        else -> "Неизвестный тип"
    }
}
```

После проверки `is` Kotlin выполняет smart cast: внутри соответствующей ветви компилятор знает более конкретный тип значения.

### 3.5. Проверка принадлежности диапазону (`in`, `!in`) {#proverka-prinadlezhnosti-diapazonu-in-in}

Операторы `in` и `!in` проверяют принадлежность значения диапазону или коллекции.

```kotlin
val age = 25

if (age in 18..65) {
    println("Рабочий возраст")
}
```

`18..65` включает оба граничных значения.

Оператор `!in` проверяет обратное условие:

```kotlin
val score = 120

if (score !in 0..100) {
    println("Некорректный результат")
}
```

`in` и `!in` можно использовать в `when`:

```kotlin
val score = 85

val grade = when (score) {
    in 90..100 -> "A"
    in 80..89 -> "B"
    in 70..79 -> "C"
    in 60..69 -> "D"
    in 0..59 -> "F"
    else -> "Некорректный балл"
}
```

Также оператор работает с коллекциями:

```kotlin
val allowedRoles = listOf("ADMIN", "MODERATOR")

val role = "ADMIN"

if (role in allowedRoles) {
    println("Доступ разрешён")
}
```

### 3.6. Вложенные условия {#vlozhennye-usloviya}

Внутри `if` можно размещать другие условия.

```kotlin
val age = 25
val hasLicense = true

if (age >= 18) {
    if (hasLicense) {
        println("Можно управлять автомобилем")
    } else {
        println("Необходимо получить права")
    }
} else {
    println("Управлять автомобилем нельзя")
}
```

Вложенные условия позволяют описывать сложную логику, но при чрезмерном количестве уровней код становится трудным для чтения.

Иногда лучше объединить условия:

```kotlin
if (age >= 18 && hasLicense) {
    println("Можно управлять автомобилем")
}
```

Или использовать ранний выход из функции:

```kotlin
fun canDrive(age: Int, hasLicense: Boolean): Boolean {
    if (age < 18) return false
    if (!hasLicense) return false

    return true
}
```

Такой стиль уменьшает вложенность и делает проверки последовательными.

### 3.7. Логические операторы (`&&`, `||`, `!`) {#logicheskie-operatory}

Kotlin предоставляет три основных логических оператора:

| Оператор | Название | Значение |
|---|---|---|
| `&&` | AND | И |
| \|\| | OR | ИЛИ |
| `!` | NOT | НЕ |

#### AND (`&&`)

Результат `true` только тогда, когда оба операнда истинны.

```kotlin
val age = 25
val hasLicense = true

if (age >= 18 && hasLicense) {
    println("Можно управлять автомобилем")
}
```

#### OR (`||`)

Результат `true`, если хотя бы один операнд истинный.

```kotlin
val isAdmin = false
val isModerator = true

if (isAdmin || isModerator) {
    println("Доступ к панели управления")
}
```

#### NOT (`!`)

Меняет логическое значение на противоположное.

```kotlin
val isAuthorized = false

if (!isAuthorized) {
    println("Необходимо авторизоваться")
}
```

#### Составные условия

Операторы можно комбинировать:

```kotlin
val age = 25
val isStudent = true
val hasDiscountCard = false

if (age >= 18 && (isStudent || hasDiscountCard)) {
    println("Доступна специальная цена")
}
```

Для сложных выражений рекомендуется использовать скобки, даже если приоритет операторов позволяет их опустить.

Так код легче читать и сложнее интерпретировать неправильно.

### 3.8. Short-circuit evaluation {#short-circuit-evaluation}

`&&` и `||` используют сокращённое вычисление (*short-circuit evaluation*).

Это означает, что второй операнд может не вычисляться, если результат уже известен по первому.

Для `&&`:

- если первый операнд `false`, весь результат уже `false`;
- второй операнд вычислять не требуется.

Для `||`:

- если первый операнд `true`, весь результат уже `true`;
- второй операнд вычислять не требуется.

Пример:

```kotlin
val userName: String? = null

if (userName != null && userName.length > 3) {
    println("Имя достаточно длинное")
}
```

Второе условие не будет вычислено, если `userName == null`.

Именно поэтому этот код безопасен.

#### Пример с побочными эффектами

```kotlin
var counter = 0

fun check(): Boolean {
    counter++
    return true
}

val result = false && check()

println(counter) // 0
```

Функция `check()` не была вызвана, потому что результат `false && anything` всегда равен `false`.

Short-circuit evaluation полезен для безопасных проверок и оптимизации вычислений.

Не стоит, однако, размещать важные побочные эффекты внутри логических выражений: пропуск их выполнения может привести к неожиданному поведению.

### Практика: Условные конструкции

1. Напиши проверку совершеннолетия пользователя.
2. Напиши функцию, которая определяет, положительное число, отрицательное или ноль.
3. Используй `if` как выражение для определения максимального из двух чисел.
4. Напиши `when`, который возвращает название дня недели по номеру.
5. Напиши `when` без аргумента, который определяет категорию температуры.
6. Проверь, входит ли число в диапазон от 10 до 100.
7. Напиши условие, которое проверяет одновременно наличие авторизации и прав администратора.
8. Используй `&&` для безопасной проверки nullable-строки.
9. Приведи пример, в котором short-circuit evaluation не позволяет выполнить вторую функцию.

#### Мини-шпаргалка: Условные конструкции

- **Два варианта поведения** — `if (cond) a else b`
- **Выбор среди нескольких вариантов** — `when (x) { ... }`
- **Условие без аргумента** — `when { cond1 -> ...; else -> ... }`
- **Проверка диапазона** — `x in 10..100`
- **Логическое И** — `&&`
- **Логическое ИЛИ** — `\|\|`
- **Отрицание** — `!`

> [!WARNING]
> **Частая ошибка:** использовать слишком длинные условия в `if`. Если условие не помещается в одну строку, вынесите его в функцию с понятным именем.

## 4. Циклы {#tsikly}

Циклы позволяют многократно выполнять один и тот же блок кода.

Они применяются, когда необходимо:

- обработать все элементы коллекции;
- выполнить действие определённое количество раз;
- повторять операцию до наступления условия;
- найти элемент в массиве;
- выполнить вычисление над последовательностью чисел.

В Kotlin существуют три основные конструкции циклов:

- `for`;
- `while`;
- `do-while`.

> **Ключевая идея:** выбирайте цикл по характеру задачи: перебор диапазона или коллекции — `for`, ожидание условия — `while`, гарантированное выполнение хотя бы один раз — `do-while`.

### 4.1. Цикл `for` {#tsikl-for}

`for` используется для обхода диапазонов, массивов и коллекций.

```kotlin
for (number in 1..5) {
    println(number)
}
```

Результат:

```text
1
2
3
4
5
```

Цикл последовательно получает значения из диапазона и присваивает их переменной `number`.

Переменная цикла доступна только внутри тела цикла.

#### Обход массива: Циклы

```kotlin
val names = arrayOf("Alex", "Maria", "John")

for (name in names) {
    println(name)
}
```

#### Обход коллекции

```kotlin
val numbers = listOf(10, 20, 30)

for (number in numbers) {
    println(number)
}
```

#### Обход с индексом

Если нужен индекс элемента, можно использовать `indices`:

```kotlin
val names = listOf("Alex", "Maria", "John")

for (index in names.indices) {
    println("$index: ${names[index]}")
}
```

Или `withIndex()`:

```kotlin
for ((index, name) in names.withIndex()) {
    println("$index: $name")
}
```

`withIndex()` удобен, когда нужны одновременно индекс и значение.

#### Обход Map

```kotlin
val users = mapOf(
    1 to "Alex",
    2 to "Maria",
    3 to "John"
)

for ((id, name) in users) {
    println("ID: $id, Name: $name")
}
```

Здесь каждая запись `Map` разбирается на ключ и значение.

### 4.2. `while` и `do-while` {#while-i-do-while}

#### `while`

`while` повторяет выполнение блока, пока условие истинно.

```kotlin
var counter = 0

while (counter < 5) {
    println(counter)
    counter++
}
```

Порядок работы:

1. Проверяется условие.
2. Если оно истинно, выполняется тело цикла.
3. Проверка выполняется снова.
4. Цикл завершается, когда условие становится ложным.

Если условие изначально ложно, тело не выполнится ни одного раза.

```kotlin
var counter = 10

while (counter < 5) {
    println(counter)
}
```

Этот цикл не выполнится.

#### `do-while`

`do-while` сначала выполняет тело, а потом проверяет условие.

```kotlin
var counter = 10

do {
    println(counter)
    counter++
} while (counter < 5)
```

Несмотря на то что условие изначально ложно, сообщение будет выведено один раз.

Главное отличие:

| `while` | `do-while` |
|---|---|
| Сначала проверяет условие | Сначала выполняет тело |
| Может не выполниться ни разу | Выполняется минимум один раз |
| Используется, когда выполнение зависит от предварительной проверки | Используется, когда действие необходимо выполнить хотя бы один раз |

#### Практический пример

Предположим, программа должна запрашивать ввод до тех пор, пока пользователь не введёт корректное значение.

```kotlin
var input: String

do {
    println("Введите имя:")
    input = readln()
} while (input.isBlank())

println("Привет, $input")
```

Ввод запрашивается как минимум один раз.

### 4.3. Диапазоны (`..`, `until`, `downTo`, `step`) {#diapazony-until-downto-step}

Kotlin позволяет легко создавать последовательности значений.

#### `..` — диапазон с включённой верхней границей

```kotlin
for (number in 1..5) {
    println(number)
}
```

Результат: `1, 2, 3, 4, 5`.

#### `until` — диапазон без верхней границы

```kotlin
for (number in 1 until 5) {
    println(number)
}
```

Результат: `1, 2, 3, 4`.

Это особенно удобно при обходе коллекций, потому что индексы начинаются с нуля:

```kotlin
val names = listOf("Alex", "Maria", "John")

for (index in 0 until names.size) {
    println(names[index])
}
```

На практике чаще используется `names.indices`, поскольку он непосредственно описывает допустимые индексы:

```kotlin
for (index in names.indices) {
    println(names[index])
}
```

#### `downTo` — обратный диапазон

```kotlin
for (number in 5 downTo 1) {
    println(number)
}
```

Результат: `5, 4, 3, 2, 1`.

#### `step` — шаг диапазона

`step` задаёт расстояние между соседними значениями.

```kotlin
for (number in 0..10 step 2) {
    println(number)
}
```

Результат: `0, 2, 4, 6, 8, 10`.

Можно комбинировать с `downTo`:

```kotlin
for (number in 10 downTo 0 step 2) {
    println(number)
}
```

Результат: `10, 8, 6, 4, 2, 0`.

#### Символьные диапазоны

Диапазоны работают не только с числами:

```kotlin
for (letter in 'A'..'E') {
    println(letter)
}
```

#### Открытые диапазоны

В современных версиях Kotlin доступен оператор `..<`, который создаёт диапазон с исключённой верхней границей.

```kotlin
for (number in 1..<5) {
    println(number)
}
```

Результат: `1, 2, 3, 4`.

По смыслу он аналогичен `1 until 5`.

### 4.4. `break` и `continue` {#break-i-continue}

Эти операторы позволяют управлять выполнением цикла.

#### `break`

`break` немедленно завершает ближайший цикл.

```kotlin
for (number in 1..10) {
    if (number == 5) {
        break
    }

    println(number)
}
```

Будут выведены числа от 1 до 4.

#### Практический пример: поиск элемента

```kotlin
val numbers = listOf(10, 20, 30, 40)
val target = 30

for (number in numbers) {
    if (number == target) {
        println("Элемент найден")
        break
    }
}
```

После нахождения элемента дальнейший обход не нужен.

#### `continue`

`continue` пропускает оставшуюся часть текущей итерации и переходит к следующей.

```kotlin
for (number in 1..5) {
    if (number == 3) {
        continue
    }

    println(number)
}
```

Результат: `1, 2, 4, 5`.

#### Практический пример: обработка только положительных чисел

```kotlin
val numbers = listOf(-5, 10, -2, 20, 0, 15)

for (number in numbers) {
    if (number <= 0) {
        continue
    }

    println(number)
}
```

Отрицательные числа и ноль пропускаются.

### 4.5. Метки для `break` и `continue` {#metki-dlya-break-i-continue}

В обычном цикле `break` и `continue` относятся к ближайшему циклу.

Если циклы вложенные, иногда необходимо управлять внешним циклом.

Для этого применяются метки.

#### `break` с меткой

```kotlin
outer@ for (i in 1..3) {
    for (j in 1..3) {
        println("i=$i, j=$j")

        if (j == 2) {
            break@outer
        }
    }
}
```

`break@outer` полностью завершит цикл, помеченный `outer`.

Без метки `break` завершил бы только внутренний цикл.

#### `continue` с меткой

```kotlin
outer@ for (i in 1..3) {
    for (j in 1..3) {
        if (j == 2) {
            continue@outer
        }

        println("i=$i, j=$j")
    }
}
```

`continue@outer` переходит к следующей итерации внешнего цикла.

Метки полезны для сложных вложенных циклов, но чрезмерное их использование часто говорит о том, что алгоритм можно упростить.

### 4.6. Вложенные циклы {#vlozhennye-tsikly}

Вложенный цикл — цикл, расположенный внутри другого цикла.

```kotlin
for (i in 1..3) {
    for (j in 1..3) {
        println("$i, $j")
    }
}
```

Для каждой итерации внешнего цикла полностью выполняется внутренний цикл.

Результат содержит девять комбинаций:

```text
1, 1
1, 2
1, 3
2, 1
2, 2
2, 3
3, 1
3, 2
3, 3
```

#### Практический пример: таблица умножения

```kotlin
for (i in 1..5) {
    for (j in 1..5) {
        print("${i * j}\t")
    }

    println()
}
```

#### Количество операций

Если внешний цикл выполняется `n` раз, а внутренний тоже `n` раз, тело внутреннего цикла выполнится `n * n` раз.

Например:

- внешний цикл — 10 итераций;
- внутренний цикл — 10 итераций;
- всего — 100 выполнений внутреннего тела.

Это важно для понимания производительности алгоритмов. Подробно сложность рассматривается в разделе «Основы алгоритмов».

### 4.7. Итерация по коллекциям {#iteratsiya-po-kollektsiyam}

Чаще всего разработчик работает не с отдельными числами, а с коллекциями данных.

```kotlin
val users = listOf(
    "Alex",
    "Maria",
    "John"
)

for (user in users) {
    println(user)
}
```

Если нужен индекс:

```kotlin
for ((index, user) in users.withIndex()) {
    println("$index: $user")
}
```

Если нужно пройти по индексам:

```kotlin
for (index in users.indices) {
    println(users[index])
}
```

Для `Map`:

```kotlin
val scores = mapOf(
    "Alex" to 90,
    "Maria" to 95,
    "John" to 80
)

for ((name, score) in scores) {
    println("$name: $score")
}
```

#### Частая ошибка: изменение коллекции во время обхода

Нельзя бездумно удалять элементы из коллекции, по которой в данный момент выполняется обход.

Например:

```kotlin
val numbers = mutableListOf(1, 2, 3, 4, 5)

// Не следует изменять коллекцию таким способом
// во время обхода.
for (number in numbers) {
    if (number % 2 == 0) {
        numbers.remove(number)
    }
}
```

Это может привести к пропуску элементов или исключению в зависимости от реализации коллекции.

Безопаснее использовать операции коллекций:

```kotlin
val numbers = mutableListOf(1, 2, 3, 4, 5)

numbers.removeAll { number ->
    number % 2 == 0
}

println(numbers) // [1, 3, 5]
```

### Практика: Циклы

1. Выведи числа от 1 до 100 с помощью `for`.
2. Выведи только чётные числа от 1 до 50.
3. С помощью `downTo` выполни обратный отсчёт от 10 до 1.
4. Вычисли сумму чисел от 1 до 100.
5. Напиши цикл `while`, который повторяется до достижения заданного значения.
6. Напиши `do-while`, который гарантированно выполнится хотя бы один раз.
7. Найди число в массиве с помощью `break`.
8. Выведи только положительные числа с помощью `continue`.
9. Создай таблицу умножения с помощью вложенных циклов.
10. Пройди по `Map` и выведи все пары ключ-значение.
11. Используй метку, чтобы завершить внешний цикл при выполнении условия.

### Самопроверка: Циклы

- [ ] Понимаю, для чего используется `for`.
- [ ] Могу обойти массив или коллекцию.
- [ ] Знаю разницу между `while` и `do-while`.
- [ ] Умею создавать диапазоны через `..` и `until`.
- [ ] Могу использовать `downTo` и `step`.
- [ ] Понимаю назначение `break` и `continue`.
- [ ] Умею использовать метки для вложенных циклов.

#### Мини-шпаргалка: Циклы

- **Перебор диапазона** — `for (i in 1..5) { ... }`
- **Перебор без последнего значения** — `for (i in 1 until 5) { ... }`
- **Обратный перебор** — `for (i in 5 downTo 1) { ... }`
- **Шаг** — `for (i in 1..10 step 2) { ... }`
- **Цикл с условием** — `while (cond) { ... }`
- **Цикл минимум один раз** — `do { ... } while (cond)`
- **Выход из цикла** — `break`
- **Пропуск итерации** — `continue`

> [!WARNING]
> **Частая ошибка:** изменять коллекцию во время её перебора. Если нужно удалить элементы, сначала соберите их, а затем измените коллекцию отдельно.

## 5. Функции {#funktsii}

Функция — именованный блок кода, который выполняет определённую задачу.

Функции позволяют разделять большую программу на небольшие логические части, повторно использовать код и уменьшать дублирование.

Например, вместо того чтобы каждый раз самостоятельно вычислять итоговую цену заказа, можно вынести расчёт в отдельную функцию.

> **Ключевая идея:** хорошая функция делает одно понятное действие, имеет осмысленное имя и явный результат.

### 5.1. Объявление и вызов функций {#obyavlenie-i-vyzov-funktsiy}

Для объявления функции используется ключевое слово `fun`.

```kotlin
fun sayHello() {
    println("Hello, Kotlin!")
}
```

Вызов функции:

```kotlin
fun main() {
    sayHello()
}
```

Имя функции — `sayHello`.

Круглые скобки содержат параметры. Фигурные скобки содержат тело функции.

#### Функция с параметрами

```kotlin
fun greet(name: String) {
    println("Привет, $name!")
}

fun main() {
    greet("Alex")
    greet("Maria")
}
```

Параметр `name` получает значение при вызове функции.

#### Функция с вычислением

```kotlin
fun calculateSum() {
    val first = 10
    val second = 20

    println(first + second)
}
```

Функция может выполнять несколько действий внутри себя.

### 5.2. Параметры и возвращаемые значения {#parametry-i-vozvraschaemye-znacheniya}

Параметры позволяют передавать функции входные данные.

Возвращаемое значение позволяет получить результат её работы.

```kotlin
fun sum(a: Int, b: Int): Int {
    return a + b
}
```

Здесь:

- `a` и `b` — параметры;
- `Int` после двоеточия — возвращаемый тип;
- `return` — возвращает результат вызывающему коду.

Использование:

```kotlin
val result = sum(10, 20)

println(result) // 30
```

#### Несколько параметров

```kotlin
fun calculateDiscount(price: Double, discountPercent: Double): Double {
    return price * discountPercent / 100
}
```

В Kotlin тип каждого параметра указывается явно.

#### Параметры доступны только для чтения

Параметры функций нельзя переназначать внутри тела функции.

```kotlin
fun printAge(age: Int) {
    // Ошибка:
    // age = 30

    println(age)
}
```

Но если параметр содержит ссылку на изменяемый объект, этот объект можно изменить:

```kotlin
fun addName(names: MutableList<String>) {
    names.add("Alex")
}

fun main() {
    val users = mutableListOf("Maria")

    addName(users)

    println(users) // [Maria, Alex]
}
```

Функция получает копию ссылки на тот же объект, поэтому изменения его изменяемого состояния видны снаружи.

Это важная особенность передачи объектов в функции.

### 5.3. Параметры по умолчанию {#parametry-po-umolchaniyu}

Kotlin позволяет указывать значения параметров по умолчанию.

```kotlin
fun greet(
    name: String,
    greeting: String = "Привет"
) {
    println("$greeting, $name!")
}
```

Вызов:

```kotlin
greet("Alex")
// Привет, Alex!

greet("Maria", "Добро пожаловать")
// Добро пожаловать, Maria!
```

Если параметр не передан, используется значение по умолчанию.

Это позволяет не создавать множество перегрузок одной и той же функции.

Например, вместо отдельных функций:

```kotlin
fun log(message: String) { ... }

fun log(message: String, tag: String) { ... }
```

Можно использовать одну:

```kotlin
fun log(message: String, tag: String = "APP") {
    println("[$tag] $message")
}
```

#### Значение по умолчанию и порядок параметров

```kotlin
fun createUser(
    name: String,
    age: Int = 18,
    isActive: Boolean = true
) {
    println("$name, $age, $isActive")
}
```

Вызовы:

```kotlin
createUser("Alex")
createUser("Maria", 25)
createUser("John", 30, false)
```

Если нужно пропустить параметр в середине, используй именованные аргументы.

### 5.4. Именованные аргументы {#imenovannye-argumenty}

Именованные аргументы позволяют явно указать, какому параметру соответствует передаваемое значение.

```kotlin
fun createUser(
    name: String,
    age: Int,
    isActive: Boolean
) {
    println("$name, $age, $isActive")
}
```

Обычный вызов:

```kotlin
createUser("Alex", 25, true)
```

Именованный вызов:

```kotlin
createUser(
    name = "Alex",
    age = 25,
    isActive = true
)
```

Преимущество особенно заметно, если несколько параметров имеют одинаковый тип или являются `Boolean`.

```kotlin
fun configureScreen(
    showToolbar: Boolean,
    showNavigation: Boolean,
    isLoading: Boolean
) {
    // ...
}
```

Не очень понятно:

```kotlin
configureScreen(true, false, true)
```

Гораздо понятнее:

```kotlin
configureScreen(
    showToolbar = true,
    showNavigation = false,
    isLoading = true
)
```

При использовании именованных аргументов их можно указывать в другом порядке:

```kotlin
createUser(
    isActive = true,
    age = 25,
    name = "Alex"
)
```

Важная особенность: Kotlin не поддерживает синтаксис именованных аргументов при вызове Java-методов, поскольку имена параметров Java не всегда сохраняются в байткоде.

### 5.5. `Unit` и expression body {#unit-i-expression-body}

Если функция не должна возвращать полезное значение, она возвращает `Unit`.

```kotlin
fun printMessage(message: String) {
    println(message)
}
```

Тип `Unit` можно указать явно, но обычно это не требуется:

```kotlin
fun printMessage(message: String): Unit {
    println(message)
}
```

#### Expression body

Если тело функции состоит из одного выражения, можно использовать сокращённый синтаксис.

```kotlin
fun sum(a: Int, b: Int): Int = a + b
```

Это называется *expression body*.

Компилятор также может вывести возвращаемый тип:

```kotlin
fun multiply(a: Int, b: Int) = a * b
```

Тип результата будет `Int`.

#### Разница между block body и expression body

Block body:

```kotlin
fun calculate(a: Int, b: Int): Int {
    val result = a + b
    return result
}
```

Expression body:

```kotlin
fun calculate(a: Int, b: Int) = a + b
```

Expression body хорошо подходит для небольших функций, когда не требуется отдельная последовательность операций.

### 5.6. Single-expression functions {#single-expression-functions}

Single-expression function — функция, тело которой состоит из одного выражения.

```kotlin
fun square(number: Int) = number * number
```

Другие примеры:

```kotlin
fun isAdult(age: Int) = age >= 18

fun getFullName(firstName: String, lastName: String) =
    "$firstName $lastName"

fun isEven(number: Int) = number % 2 == 0
```

Такие функции удобны для небольших вычислений, проверок и преобразований.

Но не стоит искусственно сокращать сложные функции. Если выражение становится трудным для понимания, лучше использовать обычное тело с несколькими понятными шагами.

### 5.7. `vararg` и spread operator {#vararg-i-spread-operator}

Иногда функции нужно передать произвольное количество аргументов.

Для этого используется `vararg`.

```kotlin
fun printNames(vararg names: String) {
    for (name in names) {
        println(name)
    }
}
```

Вызов:

```kotlin
printNames("Alex", "Maria", "John")
```

Внутри функции параметр `names` работает как массив элементов соответствующего типа.

#### Передача массива через spread operator

Если значения уже находятся в массиве, для передачи их в `vararg` используется оператор `*`.

```kotlin
fun printNames(vararg names: String) {
    println(names.joinToString())
}

val users = arrayOf("Alex", "Maria", "John")

printNames(*users)
```

Можно объединять отдельные значения и массив:

```kotlin
val users = arrayOf("Maria", "John")

printNames("Alex", *users, "Peter")
```

#### Ограничения `vararg`

Только один параметр функции может быть объявлен с `vararg`.

```kotlin
fun printInfo(
    category: String,
    vararg names: String
) {
    println(category)
    names.forEach(::println)
}
```

Если после `vararg` есть другие параметры, их обычно необходимо передавать по имени:

```kotlin
fun printInfo(
    vararg names: String,
    category: String
) {
    println(category)
    names.forEach(::println)
}

printInfo(
    "Alex",
    "Maria",
    category = "Users"
)
```

Для примитивного массива, например `IntArray`, при передаче в `vararg` типа `Int` потребуется преобразование в обычный массив:

```kotlin
fun printNumbers(vararg numbers: Int) {
    println(numbers.joinToString())
}

val values = intArrayOf(1, 2, 3)

printNumbers(*values.toTypedArray())
```

### 5.8. Локальные функции {#lokalnye-funktsii}

Функцию можно объявить внутри другой функции.

Такая функция называется локальной.

```kotlin
fun calculateOrderPrice(price: Double, discount: Double): Double {

    fun calculateDiscount(): Double {
        return price * discount / 100
    }

    return price - calculateDiscount()
}
```

Локальная функция доступна только внутри функции, в которой она объявлена.

Она может обращаться к параметрам и локальным переменным внешней функции.

```kotlin
fun processUser(name: String) {

    fun printGreeting() {
        println("Привет, $name!")
    }

    printGreeting()
}
```

Преимущества локальных функций:

- скрывают вспомогательную логику от внешнего кода;
- уменьшают количество глобальных и top-level объявлений;
- позволяют разбить сложную функцию на небольшие шаги;
- могут использовать данные внешней функции без повторной передачи параметров.

Не стоит размещать локальные функции слишком глубоко. Если функция нужна нескольким частям программы, возможно, её следует вынести отдельно.

### Практика: Функции

1. Создай функцию `greet`, принимающую имя и выводящую приветствие.
2. Создай функцию сложения двух чисел с возвращаемым значением.
3. Напиши функцию расчёта скидки с параметрами по умолчанию.
4. Вызови функцию, используя именованные аргументы.
5. Создай функцию, принимающую произвольное количество строк через `vararg`.
6. Передай в неё существующий массив через `*`.
7. Напиши функцию `isEven`, которая возвращает `Boolean`.
8. Перепиши несколько небольших функций с block body на expression body.
9. Создай локальную функцию внутри другой функции.
10. Объясни, почему параметры функции нельзя переназначать.

### Самопроверка: Функции

- [ ] Умею объявлять и вызывать функции.
- [ ] Понимаю разницу между параметрами и возвращаемыми значениями.
- [ ] Знаю, что параметры функций доступны только для чтения.
- [ ] Умею задавать значения параметров по умолчанию.
- [ ] Понимаю именованные аргументы.
- [ ] Знаю назначение `Unit`.
- [ ] Могу использовать expression body и single-expression functions.
- [ ] Понимаю работу `vararg`.
- [ ] Умею передавать массив через spread operator.
- [ ] Понимаю назначение локальных функций.

#### Мини-шпаргалка: Функции

- **Функция без результата** — `fun f() { ... }`
- **Функция с результатом** — `fun f(): Int { ... }`
- **Короткая форма** — `fun f(x: Int) = x + 1`
- **Параметр по умолчанию** — `fun f(x: Int = 0)`
- **Именованный аргумент** — `f(y = 10)`
- **Произвольное количество аргументов** — `fun f(vararg items: String)`
- **Передача массива** — `f(*array)`

> [!WARNING]
> **Частая ошибка:** делать функцию слишком длинной. Если функция не помещается на один экран, разбейте её на несколько функций с понятными именами.

## 6. ООП: основы {#oop-osnovy}

Объектно-ориентированное программирование (ООП) — подход к разработке, в котором программа строится из объектов, объединяющих данные и поведение.

Вместо того чтобы хранить все данные отдельно и выполнять над ними произвольные операции, можно создать сущности, которые отвечают за собственное состояние и связанные с ним действия.

Например, в приложении для обучения могут существовать:

- `User` — пользователь;
- `Skill` — навык;
- `Course` — курс;
- `Progress` — прогресс обучения.

У каждой сущности есть данные и поведение.

> **Ключевая идея:** сначала моделируйте предметную область через классы и объекты, а затем распределяйте ответственность между ними.

Основные концепции ООП:

1. Классы и объекты.
2. Конструкторы.
3. Наследование.
4. Интерфейсы.
5. Абстракция.
6. Инкапсуляция.
7. Полиморфизм.
8. Композиция.

### 6.1. Классы и объекты {#klassy-i-obekty}

#### Класс

Класс — описание структуры и поведения будущих объектов.

```kotlin
class User {
    val name = "Alex"
    var age = 25

    fun sayHello() {
        println("Привет, меня зовут $name")
    }
}
```

Класс `User` описывает:

- какие данные содержит пользователь;
- какие действия он умеет выполнять.

#### Объект (экземпляр класса)

Объект — конкретный экземпляр класса.

```kotlin
val user = User()
```

Теперь у нас есть объект, с которым можно работать:

```kotlin
println(user.name)
println(user.age)

user.sayHello()
```

Можно создать несколько объектов одного класса:

```kotlin
val firstUser = User()
val secondUser = User()
```

Каждый объект имеет собственное состояние экземпляра.

#### Свойства и методы

Внутри класса можно объявлять свойства и функции.

Свойства описывают состояние объекта.

Методы описывают поведение объекта.

```kotlin
class BankAccount {
    var balance = 0.0

    fun deposit(amount: Double) {
        balance += amount
    }
}
```

Использование:

```kotlin
val account = BankAccount()

account.deposit(100.0)

println(account.balance) // 100.0
```

#### Свойства класса и параметры конструктора

В Kotlin параметры первичного конструктора могут сразу объявляться свойствами:

```kotlin
class User(
    val name: String,
    var age: Int
)
```

Здесь `name` и `age` — свойства объекта.

```kotlin
val user = User("Alex", 25)

println(user.name)
println(user.age)
```

Если перед именем параметра отсутствует `val` или `var`, он не становится свойством автоматически.

```kotlin
class User(name: String) {
    val displayName = name
}
```

В этом примере `name` доступен во время инициализации класса, а `displayName` является свойством объекта.

### 6.2. Первичный и вторичные конструкторы {#pervichnyy-i-vtorichnye-konstruktory}

Конструктор определяет, как создаётся и первоначально настраивается объект.

В Kotlin есть два основных вида конструкторов:

- первичный (`primary constructor`);
- вторичный (`secondary constructor`).

#### Первичный конструктор

Объявляется в заголовке класса.

```kotlin
class User(
    val name: String,
    val age: Int
)
```

Создание объекта:

```kotlin
val user = User("Alex", 25)
```

Если для класса не нужно дополнительной логики, первичного конструктора обычно достаточно.

Параметры могут иметь значения по умолчанию:

```kotlin
class User(
    val name: String,
    val age: Int = 18
)

val user = User("Alex")
```

В таком случае `age` будет равен 18.

#### Вторичный конструктор

Вторичные конструкторы объявляются внутри тела класса с помощью `constructor`.

```kotlin
class User(
    val name: String,
    val age: Int
) {

    constructor(name: String) : this(name, 18)
}
```

Теперь объект можно создать двумя способами:

```kotlin
val first = User("Alex", 25)
val second = User("Maria")
```

Если у класса есть первичный конструктор, вторичный должен делегировать ему через `this(...)`.

Это гарантирует, что первичная инициализация класса выполнится.

#### Когда использовать вторичные конструкторы

Они могут быть полезны, когда существуют разные способы создания объекта с разными наборами входных данных.

Однако часто вместо множества вторичных конструкторов проще использовать значения параметров по умолчанию или отдельные фабричные функции.

### 6.3. Инициализаторы (`init`) {#initsializatory-init}

`init` — блок инициализации, который выполняется при создании объекта.

```kotlin
class User(
    val name: String,
    val age: Int
) {
    init {
        println("Создан пользователь: $name")
        println("Возраст: $age")
    }
}
```

Использование:

```kotlin
val user = User("Alex", 25)
```

При создании объекта выполнится код внутри `init`.

#### Проверка входных данных

`init` часто используют для проверки корректности параметров конструктора.

```kotlin
class User(
    val name: String,
    val age: Int
) {
    init {
        require(name.isNotBlank()) {
            "Имя не должно быть пустым"
        }

        require(age >= 0) {
            "Возраст не может быть отрицательным"
        }
    }
}
```

`require` выбрасывает `IllegalArgumentException`, если условие не выполняется.

Таким способом класс не позволяет создать объект с некорректным начальным состоянием.

#### Порядок инициализации

Первичный конструктор инициализирует параметры, объявленные в заголовке класса.

Затем выполняются инициализаторы свойств и блоки `init` в том порядке, в котором они расположены в теле класса.

```kotlin
class Example(val name: String) {

    val first = initialize("first")

    init {
        println("Первый init")
    }

    val second = initialize("second")

    init {
        println("Второй init")
    }

    private fun initialize(value: String): String {
        println("Инициализация: $value")
        return value
    }
}
```

Поэтому при проектировании класса важно учитывать порядок инициализации свойств.

### 6.4. Наследование (`open`, `override`, `final`, `super`) {#nasledovanie-open-override-final-super}

Наследование позволяет создать класс на основе другого класса.

Дочерний класс получает доступ к разрешённым членам родительского класса и может расширять или переопределять их поведение.

#### Почему нужен `open`

В Kotlin классы и их методы по умолчанию `final`.

Это означает, что наследование и переопределение запрещены, пока они явно не разрешены.

```kotlin
open class Animal {
    fun eat() {
        println("Животное ест")
    }
}
```

Теперь можно создать наследника:

```kotlin
class Dog : Animal()
```

Использование:

```kotlin
val dog = Dog()

dog.eat()
```

#### `override`

Если дочерний класс должен изменить реализацию метода родителя, используется `override`.

Метод родительского класса должен быть открыт через `open`:

```kotlin
open class Animal {

    open fun makeSound() {
        println("Неизвестный звук")
    }
}

class Dog : Animal() {

    override fun makeSound() {
        println("Гав!")
    }
}
```

Использование:

```kotlin
val animal = Dog()

animal.makeSound() // Гав!
```

#### `super`

`super` позволяет обратиться к реализации родительского класса.

```kotlin
open class Animal {

    open fun makeSound() {
        println("Звук животного")
    }
}

class Dog : Animal() {

    override fun makeSound() {
        super.makeSound()
        println("Гав!")
    }
}
```

Результат:

```text
Звук животного
Гав!
```

#### `final`

`final` запрещает дальнейшее переопределение или наследование.

Поскольку классы и методы Kotlin по умолчанию final, явно указывать это обычно не требуется.

Но `final` можно использовать, чтобы закрыть переопределённый метод:

```kotlin
open class Animal {
    open fun makeSound() {
        println("Звук животного")
    }
}

open class Dog : Animal() {

    final override fun makeSound() {
        println("Гав!")
    }
}
```

Теперь наследники `Dog` уже не могут переопределить `makeSound()`.

#### Наследование свойств

Переопределять можно не только функции, но и свойства, если они объявлены как `open` или являются абстрактными.

```kotlin
open class Animal {
    open val sound = "Неизвестный звук"
}

class Dog : Animal() {
    override val sound = "Гав"
}
```

#### Важное правило

Не следует без необходимости вызывать переопределяемые (`open`) методы из конструктора базового класса.

При создании наследника реализация метода может обратиться к свойствам дочернего класса, которые ещё не инициализированы.

Это способно привести к некорректному состоянию объекта.

### 6.5. Интерфейсы и их реализация {#interfeysy-i-ih-realizatsiya}

Интерфейс описывает контракт — набор свойств и функций, которые должен предоставить класс.

```kotlin
interface Printable {
    fun print()
}
```

Класс реализует интерфейс через двоеточие:

```kotlin
class Report : Printable {

    override fun print() {
        println("Отчёт")
    }
}
```

Использование:

```kotlin
val report = Report()

report.print()
```

#### Интерфейс с несколькими функциями

```kotlin
interface UserRepository {
    fun getUser(id: Int): String
    fun deleteUser(id: Int)
}
```

Любой обычный класс, реализующий этот интерфейс, должен предоставить реализацию его абстрактных членов.

```kotlin
class LocalUserRepository : UserRepository {

    override fun getUser(id: Int): String {
        return "User $id"
    }

    override fun deleteUser(id: Int) {
        println("User $id deleted")
    }
}
```

#### Реализация нескольких интерфейсов

Один класс может реализовывать несколько интерфейсов.

```kotlin
interface Printable {
    fun print()
}

interface Saveable {
    fun save()
}

class Report : Printable, Saveable {

    override fun print() {
        println("Print report")
    }

    override fun save() {
        println("Save report")
    }
}
```

В Kotlin разрешено реализовывать несколько интерфейсов, но наследоваться от нескольких классов нельзя.

#### Реализация по умолчанию

Интерфейс может содержать реализацию функции:

```kotlin
interface Logger {

    fun log(message: String) {
        println("[LOG] $message")
    }
}

class AppLogger : Logger
```

`AppLogger` получает реализацию `log()` без дополнительного кода.

Интерфейс также может объявлять свойства:

```kotlin
interface Named {
    val name: String

    val displayName: String
        get() = "Пользователь: $name"
}
```

Интерфейс может содержать абстрактные свойства и свойства с реализацией accessor, но не может хранить собственное состояние в backing field.

Это важное отличие интерфейса от класса.

### 6.6. Абстрактные классы {#abstraktnye-klassy}

Абстрактный класс объявляется с помощью `abstract`.

Он не предназначен для непосредственного создания объектов.

Вместо этого он предоставляет общую основу для дочерних классов.

```kotlin
abstract class Animal(
    val name: String
) {

    abstract fun makeSound()

    fun sleep() {
        println("$name спит")
    }
}
```

У него есть:

- абстрактный метод `makeSound()`, который не имеет реализации;
- обычный метод `sleep()`, который уже реализован.

Наследник должен реализовать абстрактные члены:

```kotlin
class Dog(name: String) : Animal(name) {

    override fun makeSound() {
        println("Гав!")
    }
}
```

Использование:

```kotlin
val dog = Dog("Шарик")

dog.makeSound()
dog.sleep()
```

#### Абстрактный класс или интерфейс?

| Абстрактный класс | Интерфейс |
|---|---|
| Нельзя создать экземпляр напрямую | Нельзя создать экземпляр напрямую |
| Может содержать состояние и backing fields | Не хранит собственное состояние в backing fields |
| Может иметь конструктор | Не имеет конструктора класса |
| Класс может наследовать только один класс | Можно реализовать несколько интерфейсов |
| Подходит для общей базовой реализации | Подходит для описания контракта |

Выбирай абстрактный класс, когда у группы сущностей есть общая базовая структура и состояние.

Выбирай интерфейс, когда нужно описать способность или контракт, который могут реализовать разные классы.

### 6.7. Инкапсуляция {#inkapsulyatsiya}

Инкапсуляция — принцип сокрытия внутреннего состояния объекта и предоставления контролируемого доступа к нему.

Предположим, есть банковский счёт.

Плохой вариант:

```kotlin
class BankAccount {
    var balance = 0.0
}
```

Любой внешний код может присвоить произвольное значение:

```kotlin
val account = BankAccount()

account.balance = -1_000_000.0
```

Класс не защищает своё состояние.

Более правильный вариант:

```kotlin
class BankAccount {

    var balance: Double = 0.0
        private set

    fun deposit(amount: Double) {
        require(amount > 0)

        balance += amount
    }

    fun withdraw(amount: Double): Boolean {
        require(amount > 0)

        if (balance < amount) {
            return false
        }

        balance -= amount
        return true
    }
}
```

Теперь внешний код может прочитать баланс, но не может изменить его напрямую.

Изменение проходит через методы, которые проверяют корректность операции.

#### Модификаторы доступа

| Модификатор | Назначение |
|---|---|
| `public` | Публичный доступ |
| `private` | Доступ только внутри соответствующей области объявления |
| `protected` | Доступ внутри класса и наследников |
| `internal` | Доступ внутри текущего модуля |

По умолчанию Kotlin использует `public`.

#### Почему инкапсуляция важна

Она помогает:

- защищать объект от некорректного состояния;
- ограничивать количество точек изменения данных;
- скрывать детали реализации;
- менять внутреннюю реализацию без изменения внешнего API;
- делать поведение объекта более предсказуемым.

### 6.8. Полиморфизм {#polimorfizm}

Полиморфизм — возможность работать с объектами разных типов через общий тип.

Рассмотрим пример:

```kotlin
open class Animal {
    open fun makeSound() {
        println("Неизвестный звук")
    }
}

class Dog : Animal() {
    override fun makeSound() {
        println("Гав")
    }
}

class Cat : Animal() {
    override fun makeSound() {
        println("Мяу")
    }
}
```

Теперь можно написать функцию, которая работает с любым `Animal`:

```kotlin
fun makeAnimalSpeak(animal: Animal) {
    animal.makeSound()
}
```

Использование:

```kotlin
makeAnimalSpeak(Dog())
makeAnimalSpeak(Cat())
```

Результат:

```text
Гав
Мяу
```

Функция не знает конкретный тип объекта, но получает нужное поведение благодаря переопределению метода.

#### Полиморфизм через интерфейсы

Для полиморфизма не обязательно использовать наследование от класса.

```kotlin
interface Payable {
    fun pay(amount: Double)
}

class CardPayment : Payable {
    override fun pay(amount: Double) {
        println("Оплата картой: $amount")
    }
}

class CashPayment : Payable {
    override fun pay(amount: Double) {
        println("Оплата наличными: $amount")
    }
}
```

Общий код:

```kotlin
fun processPayment(
    payment: Payable,
    amount: Double
) {
    payment.pay(amount)
}
```

Теперь способ оплаты можно менять без изменения `processPayment`.

Это один из ключевых способов уменьшить связанность между частями приложения.

### 6.9. Композиция объектов {#kompozitsiya-obektov}

Композиция — построение объекта из других объектов.

Вместо наследования один класс может содержать внутри себя экземпляры других классов и делегировать им часть работы.

Например, автомобиль состоит из двигателя:

```kotlin
class Engine {
    fun start() {
        println("Двигатель запущен")
    }
}

class Car(
    private val engine: Engine
) {

    fun start() {
        engine.start()
        println("Автомобиль готов к движению")
    }
}
```

Использование:

```kotlin
val engine = Engine()
val car = Car(engine)

car.start()
```

Здесь `Car` не наследуется от `Engine`.

Он использует `Engine` как составную часть своей реализации.

#### Наследование и композиция

| Наследование | Композиция |
|---|---|
| Отношение «является» (is-a) | Отношение «содержит» (has-a) |
| Класс расширяет другой класс | Класс использует другой объект |
| Поведение наследуется | Поведение делегируется |
| Создаёт связь между классами на уровне иерархии | Позволяет заменять зависимости |
| Может усложнять иерархию | Часто даёт большую гибкость |

Например:

- `Dog` является `Animal` — наследование.
- `Car` содержит `Engine` — композиция.
- `OrderService` использует `PaymentRepository` — композиция.

В прикладной разработке часто предпочитают композицию, поскольку она позволяет собирать поведение из небольших независимых компонентов.

#### Пример с заменяемой зависимостью

```kotlin
interface PaymentProcessor {
    fun pay(amount: Double)
}

class CardProcessor : PaymentProcessor {
    override fun pay(amount: Double) {
        println("Оплата картой: $amount")
    }
}

class CashProcessor : PaymentProcessor {
    override fun pay(amount: Double) {
        println("Оплата наличными: $amount")
    }
}

class OrderService(
    private val paymentProcessor: PaymentProcessor
) {
    fun checkout(amount: Double) {
        paymentProcessor.pay(amount)
    }
}
```

Теперь `OrderService` не зависит от конкретного способа оплаты.

```kotlin
val cardService = OrderService(CardProcessor())
val cashService = OrderService(CashProcessor())

cardService.checkout(100.0)
cashService.checkout(200.0)
```

Это простой пример принципа композиции и зависимости от абстракций.

### Практика: ООП: основы

1. Создай класс `User` со свойствами `name`, `age` и методом `printInfo()`.

4. Создай базовый класс `Animal` и двух наследников `Dog` и `Cat`.

## 7. Коллекции {#kollektsii}

Коллекции — структуры данных, которые позволяют хранить и обрабатывать группы элементов.

В реальных приложениях почти всегда приходится работать с наборами данных:

- списком пользователей;
- историей операций;
- товарами;
- сообщениями чата;
- результатами запросов;
- настройками;
- наборами навыков и категорий.

Kotlin предоставляет стандартную библиотеку коллекций с удобными интерфейсами и функциями обработки данных.

Основные типы коллекций:

- `List`;
- `Set`;
- `Map`.

> **Ключевая идея:** выбирайте коллекцию по задаче: порядок — `List`, уникальность — `Set`, поиск по ключу — `Map`. По умолчанию предпочитайте read-only коллекции.

### 7.1. `List` и `MutableList` {#list-i-mutablelist}

#### `List`

`List` представляет упорядоченную коллекцию элементов.

Особенности:

- порядок элементов сохраняется;
- каждый элемент имеет индекс;
- элементы могут повторяться;
- доступ к элементу выполняется по индексу.

Создание:

```kotlin
val names = listOf("Alex", "Maria", "John")
```

Доступ к элементам:

```kotlin
println(names[0]) // Alex
println(names[1]) // Maria
println(names[2]) // John
```

Индексы начинаются с нуля.

Размер:

```kotlin
println(names.size) // 3
```

Проверка наличия элемента:

```kotlin
println("Alex" in names) // true
```

`List` предоставляет интерфейс только для чтения.

Через переменную типа `List` нельзя добавлять или удалять элементы.

#### `MutableList`

`MutableList` — изменяемый список.

```kotlin
val names = mutableListOf("Alex", "Maria")
```

Добавление:

```kotlin
names.add("John")
```

Удаление:

```kotlin
names.remove("Maria")
```

Удаление по индексу:

```kotlin
names.removeAt(0)
```

Изменение элемента:

```kotlin
names[0] = "Peter"
```

Вставка по индексу:

```kotlin
names.add(0, "Anna")
```

Пример:

```kotlin
val names = mutableListOf("Alex", "Maria")

names.add("John")
names.add(0, "Peter")
names.remove("Maria")

println(names)
```

#### `List` и `MutableList`

| `List` | `MutableList` |
|---|---|
| Интерфейс только для чтения | Интерфейс с операциями изменения |
| Нельзя вызвать `add()` | Можно вызвать `add()` |
| Нельзя вызвать `remove()` | Можно вызвать `remove()` |
| Нельзя изменить элемент через индекс | Можно изменить элемент через индекс |

Важно: тип `List` не гарантирует, что сама коллекция физически неизменяема. Он лишь не предоставляет операции изменения через данный интерфейс.

Например:

```kotlin
val mutableNames = mutableListOf("Alex")

val readOnlyNames: List<String> = mutableNames

mutableNames.add("Maria")

println(readOnlyNames) // [Alex, Maria]
```

Обе переменные ссылаются на один объект.

Поэтому `List` следует понимать как read-only интерфейс, а не как абсолютную гарантию immutable-объекта.

### 7.2. `Set` и `MutableSet` {#set-i-mutableset}

`Set` хранит уникальные элементы.

Дубликаты не допускаются.

```kotlin
val numbers = setOf(1, 2, 3, 2, 1)

println(numbers) // [1, 2, 3]
```

Повторяющиеся значения не создают дополнительные элементы.

Основные особенности:

- каждый элемент уникален;
- нет доступа к элементам по индексу;
- порядок элементов не является общим контрактом `Set`.

Проверка наличия:

```kotlin
val roles = setOf("ADMIN", "USER", "MODERATOR")

println("ADMIN" in roles) // true
```

#### `MutableSet`

Для изменяемого множества используется `mutableSetOf()`:

```kotlin
val roles = mutableSetOf("ADMIN", "USER")

roles.add("MODERATOR")
roles.add("USER")

println(roles)
```

Вторая попытка добавить `USER` не создаёт дубликат.

Удаление:

```kotlin
roles.remove("ADMIN")
```

#### Когда использовать Set

`Set` подходит, когда важна уникальность значений:

- уникальные идентификаторы;
- роли пользователя;
- набор доступных разрешений;
- посещённые страницы;
- выбранные категории.

Например:

```kotlin
val visitedPages = mutableSetOf<String>()

visitedPages.add("/home")
visitedPages.add("/profile")
visitedPages.add("/home")

println(visitedPages.size) // 2
```

### 7.3. `Map` и `MutableMap` {#map-i-mutablemap}

`Map` хранит пары «ключ — значение».

Каждый ключ уникален, а значения могут повторяться.

Например:

```kotlin
val users = mapOf(
    1 to "Alex",
    2 to "Maria",
    3 to "John"
)
```

Здесь:

- `1`, `2`, `3` — ключи;
- `"Alex"`, `"Maria"`, `"John"` — значения.

#### Получение значения

```kotlin
println(users[1]) // Alex
```

Если ключ отсутствует, оператор `[]` возвращает `null`.

```kotlin
println(users[100]) // null
```

Поэтому результат обращения к Map часто имеет nullable-тип.

#### Получение ключей и значений

```kotlin
println(users.keys)
println(users.values)
```

#### Проверка ключа

```kotlin
if (1 in users) {
    println("Пользователь существует")
}
```

#### `MutableMap`

Изменяемая версия:

```kotlin
val users = mutableMapOf(
    1 to "Alex",
    2 to "Maria"
)
```

Добавление новой пары:

```kotlin
users[3] = "John"
```

Обновление значения:

```kotlin
users[1] = "Peter"
```

Удаление:

```kotlin
users.remove(2)
```

Получение значения с запасным вариантом:

```kotlin
val userName = users.getOrDefault(100, "Unknown")
```

#### Особенности ключей

Ключи должны быть уникальными.

Если добавить пару с уже существующим ключом, старое значение будет заменено.

```kotlin
val users = mutableMapOf(
    1 to "Alex"
)

users[1] = "Maria"

println(users[1]) // Maria
```

#### Когда использовать Map

`Map` полезен, когда необходимо быстро получать значение по ключу или хранить логические связи.

Примеры:

- `userId -> userName`;
- `productId -> price`;
- `languageCode -> locale`;
- `settingKey -> settingValue`.

### 7.4. Read-only vs mutable collections {#read-only-vs-mutable-collections}

В Kotlin есть два основных набора интерфейсов коллекций:

**Read-only:**

- `List`;
- `Set`;
- `Map`.

**Mutable:**

- `MutableList`;
- `MutableSet`;
- `MutableMap`.

```kotlin
val readOnlyList: List<Int> = listOf(1, 2, 3)

val mutableList: MutableList<Int> = mutableListOf(1, 2, 3)
```

Главное отличие — доступные операции.

```kotlin
mutableList.add(4)

// Ошибка:
// readOnlyList.add(4)
```

#### Почему это важно: Коллекции

Представь, что репозиторий возвращает список пользователей:

```kotlin
fun getUsers(): List<String> {
    return listOf("Alex", "Maria")
}
```

Потребитель получает список только для чтения.

Он может:

- читать элементы;
- итерироваться;
- искать элементы;
- фильтровать их.

Но не может изменять исходную коллекцию через этот интерфейс.

Это делает API более предсказуемым.

#### `val` и mutable-коллекция

Не путай неизменяемость ссылки и изменяемость коллекции.

```kotlin
val names = mutableListOf("Alex")

names.add("Maria") // Разрешено.

// names = mutableListOf("John") // Ошибка.
```

`val` защищает переменную от повторного присваивания, но не запрещает операции над объектом.

Для разработки рекомендуется предпочитать read-only интерфейсы там, где изменение коллекции не требуется.

### 7.5. Итерация по коллекциям {#iteratsiya-po-kollektsiyam-2}

Коллекции можно обходить с помощью `for`:

```kotlin
val names = listOf("Alex", "Maria", "John")

for (name in names) {
    println(name)
}
```

Если нужен индекс:

```kotlin
for ((index, name) in names.withIndex()) {
    println("$index: $name")
}
```

`Set` обходится аналогично:

```kotlin
val roles = setOf("ADMIN", "USER")

for (role in roles) {
    println(role)
}
```

`Map`:

```kotlin
val scores = mapOf(
    "Alex" to 90,
    "Maria" to 95
)

for ((name, score) in scores) {
    println("$name: $score")
}
```

Можно обращаться отдельно к ключам и значениям:

```kotlin
for (key in scores.keys) {
    println(key)
}

for (value in scores.values) {
    println(value)
}
```

### 7.6. Основные операции (`filter`, `map`, `find`, `first`, `any`, `all`) {#osnovnye-operatsii-filter-map-find-first-any-all}

Kotlin предоставляет большое количество готовых функций для обработки коллекций.

Они позволяют писать преобразования без ручного создания циклов.

#### `filter`

`filter` оставляет только элементы, удовлетворяющие условию.

```kotlin
val numbers = listOf(1, 2, 3, 4, 5, 6)

val evenNumbers = numbers.filter { number ->
    number % 2 == 0
}

println(evenNumbers) // [2, 4, 6]
```

#### `map`

`map` преобразует каждый элемент в новое значение.

```kotlin
val numbers = listOf(1, 2, 3)

val squares = numbers.map { number ->
    number * number
}

println(squares) // [1, 4, 9]
```

Число элементов сохраняется: каждому исходному элементу соответствует один результат.

Пример преобразования объектов:

```kotlin
data class User(
    val name: String,
    val age: Int
)

val users = listOf(
    User("Alex", 25),
    User("Maria", 30)
)

val names = users.map { user ->
    user.name
}

println(names) // [Alex, Maria]
```

#### `find`

`find` возвращает первый элемент, удовлетворяющий условию.

Если подходящего элемента нет, возвращается `null`.

```kotlin
val numbers = listOf(1, 3, 5, 8, 10)

val result = numbers.find { it % 2 == 0 }

println(result) // 8
```

Если элемент отсутствует:

```kotlin
val result = numbers.find { it < 0 }

println(result) // null
```

Поэтому результат `find` имеет nullable-тип.

#### `first`

`first()` возвращает первый элемент коллекции:

```kotlin
val names = listOf("Alex", "Maria", "John")

println(names.first()) // Alex
```

Можно использовать условие:

```kotlin
val numbers = listOf(1, 2, 3, 4)

val result = numbers.first { it > 2 }

println(result) // 3
```

Важно: `first()` выбрасывает `NoSuchElementException`, если коллекция пуста или нет подходящего элемента.

Если наличие результата не гарантируется, используй `firstOrNull()`:

```kotlin
val result = numbers.firstOrNull { it > 10 }

println(result) // null
```

#### `any`

`any` проверяет, есть ли хотя бы один элемент, удовлетворяющий условию.

```kotlin
val numbers = listOf(1, 2, 3, 4)

val hasEven = numbers.any { it % 2 == 0 }

println(hasEven) // true
```

Без условия проверяет, что коллекция не пустая:

```kotlin
println(numbers.any())
```

#### `all`

`all` проверяет, удовлетворяют ли условию все элементы.

```kotlin
val numbers = listOf(2, 4, 6)

val allEven = numbers.all { it % 2 == 0 }

println(allEven) // true
```

Если хотя бы один элемент не подходит, результат будет `false`.

Особенность: `all` для пустой коллекции возвращает `true`, поскольку ни одного элемента, нарушающего условие, не существует.

#### Сводная таблица

| Функция | Назначение | Результат |
|---|---|---|
| `filter` | Отбирает элементы | Новая коллекция |
| `map` | Преобразует элементы | Новая коллекция |
| `find` | Ищет первый подходящий элемент | Элемент или `null` |
| `first` | Получает первый элемент | Элемент или исключение |
| `firstOrNull` | Безопасно получает первый элемент | Элемент или `null` |
| `any` | Проверяет наличие подходящего элемента | `Boolean` |
| `all` | Проверяет все элементы | `Boolean` |

#### Важное свойство операций

Операции `filter` и `map` не изменяют исходную коллекцию.

```kotlin
val numbers = listOf(1, 2, 3, 4)

numbers.filter { it > 2 }

println(numbers) // [1, 2, 3, 4]
```

Результат `filter` был создан, но потерян, потому что его никуда не сохранили.

Правильно:

```kotlin
val filtered = numbers.filter { it > 2 }

println(filtered) // [3, 4]
```

### 7.7. Добавление и удаление элементов {#dobavlenie-i-udalenie-elementov}

Для изменения коллекции используются mutable-интерфейсы.

#### List

```kotlin
val names = mutableListOf("Alex", "Maria")

names.add("John")
names.add(0, "Peter")

names.remove("Maria")
names.removeAt(0)

names[0] = "Anna"
```

#### Set

```kotlin
val roles = mutableSetOf("USER")

roles.add("ADMIN")
roles.add("USER") // Дубликат не появится.

roles.remove("USER")
```

#### Map

```kotlin
val users = mutableMapOf(
    1 to "Alex"
)

users[2] = "Maria"
users[1] = "John"

users.remove(2)
```

Операции изменения недоступны через read-only интерфейсы.

### 7.8. Выбор коллекции под задачу {#vybor-kollektsii-pod-zadachu}

Выбор коллекции зависит от того, как программа будет использовать данные.

| Задача | Подходящая коллекция | Причина |
|---|---|---|
| Хранить список пользователей | `List` | Важен порядок, возможны повторения |
| Хранить список операций | `List` | Порядок выполнения имеет значение |
| Хранить уникальные роли | `Set` | Дубликаты не нужны |
| Хранить уникальные ID | `Set` | Требуется уникальность |
| Хранить пользователя по ID | `Map` | Доступ по ключу |
| Хранить настройки по ключу | `Map` | Связь ключ-значение |
| Нужен список с добавлением и удалением | `MutableList` | Изменяемая коллекция |
| Нужен набор уникальных изменяемых значений | `MutableSet` | Можно добавлять и удалять элементы |
| Нужны изменяемые пары ключ-значение | `MutableMap` | Можно менять записи |

#### Разница между массивом и списком

| Array | List |
|---|---|
| Фиксированный размер | Размер может меняться у mutable-реализаций |
| Элементы изменяемы | Read-only или mutable API |
| Нет встроенного `add()` | `MutableList` предоставляет `add()` |
| `==` сравнивает ссылки | `==` сравнивает содержимое |
| Есть специализированные primitive arrays | Элементы обычно представлены объектами на JVM |

Для обычной прикладной разработки чаще выбирай `List`, `Set` и `Map`.

Массивы применяй, когда есть конкретная причина.

### Практика: Коллекции

1. Создай список пользователей через `listOf()`.
2. Создай изменяемый список и добавь в него несколько элементов.
3. Удали элемент по значению и по индексу.
4. Создай `Set` с повторяющимися значениями и убедись, что дубликаты не сохраняются.
5. Создай `Map`, где ключ — ID пользователя, а значение — его имя.
6. Добавь и измени элементы в `MutableMap`.
7. Отфильтруй список чисел через `filter`, оставив только чётные.
8. Используй `map`, чтобы получить квадраты всех чисел.
9. Найди первый элемент, удовлетворяющий условию, через `find`.
10. Проверь, есть ли в списке хотя бы один отрицательный элемент через `any`.
11. Проверь, все ли числа положительные через `all`.
12. Объясни, почему вызов `filter` без сохранения результата не изменяет исходный список.

## 8. Обработка ошибок {#obrabotka-oshibok}

Во время выполнения программы могут возникать ситуации, когда операция не может быть выполнена корректно.

Например:

- пользователь ввёл неправильные данные;
- файл не существует;
- сервер недоступен;
- число невозможно преобразовать из строки;
- программа получила некорректное состояние.

Обработка ошибок позволяет управлять такими ситуациями, чтобы приложение не завершалось неожиданно и могло корректно сообщить о проблеме.

В Kotlin существуют несколько механизмов:

- исключения (`Exception`);
- обработка через `try / catch / finally`;
- оператор `throw`;
- nullable-типы;
- безопасный доступ `?.`;
- Elvis operator `?:`;
- `runCatching`;
- `Result`;
- собственные типы результатов на основе `sealed class` или `sealed interface`.

> **Ключевая идея:** ошибка — это тоже ожидаемый сценарий. Обрабатывайте её на том уровне, где можно принять осмысленное решение: показать сообщение, повторить операцию или вернуть безопасный результат.

### 8.1. Иерархия `Throwable`, `Exception` и `Error` {#ierarhiya-throwable-exception-i-error}

В Kotlin корнем иерархии исключений является `Throwable`.

У него есть два основных наследника:

- `Exception`;
- `Error`.

Упрощённая схема:

```text
Throwable
├── Exception
│   ├── RuntimeException
│   ├── IllegalArgumentException
│   ├── IllegalStateException
│   └── ...
│
└── Error
    ├── OutOfMemoryError
    ├── StackOverflowError
    └── ...
```

#### `Throwable`

Базовый тип всех объектов, которые могут быть выброшены через `throw` и перехвачены через `catch`.

#### `Exception`

Описывает исключительные ситуации, которые программа в определённых случаях может обработать.

Примеры:

- некорректный аргумент;
- неправильное состояние;
- ошибка ввода-вывода;
- ошибка преобразования данных.

#### `Error`

Описывает серьёзные проблемы выполнения или среды, от которых приложение обычно не может безопасно восстановиться.

Например:

- `OutOfMemoryError` — недостаточно памяти;
- `StackOverflowError` — переполнение стека вызовов.

#### Нужно ли перехватывать `Throwable`?

В большинстве прикладного кода не стоит перехватывать `Throwable` без особой причины.

Если перехватывать всё подряд, можно скрыть серьёзные проблемы, которые программа не должна пытаться обрабатывать как обычную бизнес-ошибку.

Обычно следует перехватывать конкретные исключения, которые действительно можно обработать.

#### Checked и unchecked exceptions

В Kotlin исключения по умолчанию являются unchecked.

Это означает, что функция не обязана объявлять исключения в своей сигнатуре и вызывающий код не обязан явно обрабатывать их.

В отличие от Java, Kotlin не имеет механизма обязательного объявления checked exceptions.

### 8.2. `try / catch / finally` {#try-catch-finally}

Для обработки исключений используется конструкция `try / catch`.

```kotlin
try {
    val result = 10 / 0
    println(result)
} catch (e: ArithmeticException) {
    println("Ошибка деления")
}
```

Когда внутри `try` возникает подходящее исключение:

1. Обычное выполнение блока прерывается.
2. Kotlin ищет подходящий `catch`.
3. Если подходящий обработчик найден, выполняется его тело.
4. После завершения обработки программа продолжает выполнение после конструкции `try-catch`.

#### Несколько блоков `catch`

Можно обрабатывать разные типы исключений отдельно:

```kotlin
try {
    val number = "abc".toInt()
    println(10 / number)
} catch (e: NumberFormatException) {
    println("Некорректное число")
} catch (e: ArithmeticException) {
    println("Деление на ноль")
}
```

Порядок обработчиков имеет значение.

Сначала размещай более конкретные типы исключений, затем более общие.

```kotlin
try {
    // ...
} catch (e: NumberFormatException) {
    // ...
} catch (e: IllegalArgumentException) {
    // ...
} catch (e: Exception) {
    // ...
}
```

`NumberFormatException` является наследником `IllegalArgumentException`, поэтому более общий обработчик не должен стоять раньше конкретного.

#### Получение информации об исключении

```kotlin
try {
    val number = "abc".toInt()
} catch (e: NumberFormatException) {
    println(e.message)
}
```

Исключение содержит полезную диагностическую информацию:

- тип исключения;
- сообщение;
- стек вызовов;
- причину исключения, если она была передана.

Не следует без необходимости показывать пользователю технический stack trace.

### 8.3. `finally` {#finally}

Блок `finally` выполняется после `try` и `catch` независимо от того, произошло исключение или нет.

```kotlin
try {
    println("Начало операции")

    val result = 10 / 2

    println(result)
} catch (e: ArithmeticException) {
    println("Произошла ошибка")
} finally {
    println("Операция завершена")
}
```

Типичные применения:

- освобождение ресурсов;
- закрытие соединений;
- очистка временного состояния;
- завершение операций, которые должны выполниться при обычном выходе из блока.

#### Важный нюанс

`finally` не предназначен для изменения результата `try` и не должен использоваться для неожиданных `return` или выброса новых исключений.

Если требуется работа с ресурсом, который нужно закрыть, на JVM часто предпочтительнее использовать `use()`:

```kotlin
// Пример для JVM:
// File("data.txt").bufferedReader().use { reader ->
//     println(reader.readLine())
// }
```

`use` автоматически закрывает ресурс после выполнения блока.

### 8.4. Оператор `throw` {#operator-throw}

`throw` позволяет самостоятельно выбросить исключение.

```kotlin
fun withdraw(balance: Double, amount: Double) {
    if (amount <= 0) {
        throw IllegalArgumentException("Сумма должна быть положительной")
    }

    if (amount > balance) {
        throw IllegalStateException("Недостаточно средств")
    }
}
```

Два распространённых типа исключений:

#### `IllegalArgumentException`

Используется, когда вызывающий код передал некорректный аргумент.

```kotlin
fun calculateAge(birthYear: Int): Int {
    require(birthYear > 0)

    return 2026 - birthYear
}
```

#### `IllegalStateException`

Используется, когда операция недопустима для текущего состояния объекта или системы.

```kotlin
class Player {

    private var isPlaying = false

    fun stop() {
        check(isPlaying) {
            "Плеер ещё не запущен"
        }

        isPlaying = false
    }
}
```

`require` и `check` — стандартные функции Kotlin:

- `require(condition)` выбрасывает `IllegalArgumentException`;
- `check(condition)` выбрасывает `IllegalStateException`.

Они позволяют удобно проверять предусловия и состояние.

#### Собственные исключения

Можно объявить собственный тип исключения:

```kotlin
class InsufficientBalanceException(
    message: String
) : Exception(message)
```

Использование:

```kotlin
fun withdraw(balance: Double, amount: Double): Double {
    if (amount > balance) {
        throw InsufficientBalanceException("Недостаточно средств")
    }

    return balance - amount
}
```

Собственные исключения полезны, когда необходимо различать конкретные причины отказа.

### 8.5. Nullable-типы и безопасный доступ {#nullable-tipy-i-bezopasnyy-dostup}

Одна из важных особенностей Kotlin — поддержка null safety на уровне системы типов.

Обычная переменная не может содержать `null`:

```kotlin
val name: String = "Alex"

// Ошибка:
// val name: String = null
```

Nullable-переменная может:

```kotlin
val name: String? = null
```

Знак `?` после типа означает, что значение может отсутствовать.

#### Проверка на null

```kotlin
val name: String? = "Alex"

if (name != null) {
    println(name.length)
}
```

После проверки Kotlin понимает, что `name` не равен `null`, и позволяет обращаться к его свойствам.

Это называется smart cast.

#### Safe call operator (`?.`)

Если объект может быть `null`, безопасный оператор `?.` позволяет обратиться к его свойству или методу только при наличии значения.

```kotlin
val name: String? = null

println(name?.length) // null
```

Если `name` не равен `null`, вернётся длина строки.

Если `null`, результатом тоже будет `null`, а исключение не возникнет.

#### Цепочка безопасных вызовов

```kotlin
class Address(
    val city: String
)

class User(
    val address: Address?
)

val user = User(
    address = Address("Helsinki")
)

val city = user.address?.city
```

Если `address` отсутствует, `city` тоже получит `null`.

#### Безопасный вызов функции

```kotlin
fun printName(name: String?) {
    println(name?.uppercase())
}
```

Если имя отсутствует, функция ничего не вызовет и выведет `null`.

### 8.6. Elvis operator (`?:`) {#elvis-operator}

Elvis operator позволяет задать значение по умолчанию, если выражение слева равно `null`.

```kotlin
val name: String? = null

val result = name ?: "Unknown"

println(result) // Unknown
```

Если `name` не равен `null`, возвращается его значение.

Если `name == null`, используется значение справа.

#### Пример с длиной строки

```kotlin
val text: String? = null

val length = text?.length ?: 0

println(length) // 0
```

Это аналогично:

```kotlin
val length = if (text != null) {
    text.length
} else {
    0
}
```

#### Ранний выход через Elvis

Elvis operator можно использовать вместе с `return`:

```kotlin
fun printUserName(name: String?) {
    val actualName = name ?: return

    println(actualName)
}
```

Если `name == null`, функция завершится.

Также можно выбросить исключение:

```kotlin
fun getUserName(name: String?): String {
    return name ?: throw IllegalArgumentException(
        "Имя пользователя отсутствует"
    )
}
```

Это удобно для проверки обязательных значений.

### 8.7. Not-null assertion (`!!`) и связанные риски {#not-null-assertion-i-svyazannye-riski}

Оператор `!!` принудительно преобразует nullable-значение в non-nullable.

```kotlin
val name: String? = "Alex"

val actualName: String = name!!

println(actualName.length)
```

Если значение не равно `null`, операция пройдёт успешно.

Если оно равно `null`, возникнет `NullPointerException`.

```kotlin
val name: String? = null

// Вызовет NullPointerException:
// println(name!!.length)
```

#### Почему `!!` опасен

Он фактически отключает защиту null safety в конкретном месте кода.

Вместо обработки возможного отсутствия значения программа получает ошибку выполнения.

Предпочтительные альтернативы:

```kotlin
// Вариант 1: безопасный вызов.
val length = name?.length

// Вариант 2: значение по умолчанию.
val safeLength = name?.length ?: 0

// Вариант 3: явная проверка.
if (name != null) {
    println(name.length)
}
```

Использование `!!` допустимо только тогда, когда есть надёжная гарантия, что значение не может быть `null`.

Однако даже в этом случае часто существуют более безопасные способы выразить условие.

### 8.8. `runCatching` {#runcatching}

`runCatching` позволяет выполнить блок кода и представить результат как объект `Result`.

```kotlin
val result = runCatching {
    "123".toInt()
}
```

Если операция завершилась успешно, `Result` содержит значение.

Если произошла ошибка, `Result` содержит исключение.

#### Обработка результата

```kotlin
val result = runCatching {
    "123".toInt()
}

result
    .onSuccess { number ->
        println("Получено число: $number")
    }
    .onFailure { error ->
        println("Ошибка: ${error.message}")
    }
```

#### Безопасное преобразование

```kotlin
fun parseNumber(value: String): Result<Int> {
    return runCatching {
        value.toInt()
    }
}
```

Использование:

```kotlin
val result = parseNumber("123")

val number = result.getOrNull()

println(number) // 123
```

Если преобразование не удалось, `getOrNull()` вернёт `null`.

#### Полезные операции `Result`

| Операция | Назначение |
|---|---|
| `isSuccess` | Проверяет успешный результат |
| `isFailure` | Проверяет наличие ошибки |
| `getOrNull()` | Возвращает значение или `null` |
| `getOrThrow()` | Возвращает значение или выбрасывает исключение |
| `getOrElse {}` | Возвращает значение либо вычисляет запасной вариант |
| `onSuccess {}` | Выполняет действие при успехе |
| `onFailure {}` | Выполняет действие при ошибке |
| `fold()` | Обрабатывает обе ветви и возвращает общий результат |

Пример с `fold()`:

```kotlin
val result = runCatching {
    "123".toInt()
}

val message = result.fold(
    onSuccess = { number ->
        "Получено число: $number"
    },
    onFailure = { error ->
        "Ошибка: ${error.message}"
    }
)

println(message)
```

#### Важная особенность `runCatching`

`runCatching` перехватывает любой `Throwable`, а не только обычные `Exception`.

Поэтому его не следует использовать бездумно вокруг больших участков кода.

В частности, при работе с корутинами важно не поглотить `CancellationException`: отмена корутины является частью механизма управления её жизненным циклом, а не обычной ошибкой бизнес-операции.

Если `runCatching` используется внутри suspend-кода, отмену обычно нужно повторно выбрасывать:

```kotlin
suspend fun loadData(): Result<String> {
    return runCatching {
        performSuspendOperation()
    }.onFailure { error ->
        if (error is kotlinx.coroutines.CancellationException) {
            throw error
        }
    }
}
```

В дальнейшем при изучении корутин этот нюанс станет особенно важным.

### 8.9. Представление результата: `Result` и `sealed class` {#predstavlenie-rezultata-result-i-sealed-class}

Не каждая неуспешная операция обязательно должна завершаться исключением.

Например, при авторизации возможны разные результаты:

- пользователь успешно авторизован;
- неправильный пароль;
- пользователь не найден;
- аккаунт заблокирован.

Можно представить результат через `Result` или собственную иерархию типов.

#### `Result<T>`

`Result<T>` представляет один из двух вариантов:

- успешный результат типа `T`;
- исключение типа `Throwable`.

Пример:

```kotlin
fun parseAge(value: String): Result<Int> {
    return runCatching {
        value.toInt()
    }
}
```

Преимущество — простой способ передать значение или исключение.

Недостаток — `Result` не описывает конкретные бизнес-сценарии на уровне типов.

#### Sealed class

`sealed class` позволяет ограничить набор возможных вариантов результата.

```kotlin
sealed class LoginResult {

    data class Success(
        val userName: String
    ) : LoginResult()

    data object InvalidPassword : LoginResult()

    data object UserNotFound : LoginResult()

    data object AccountBlocked : LoginResult()
}
```

Функция авторизации:

```kotlin
fun login(
    userName: String,
    password: String
): LoginResult {
    if (userName.isBlank()) {
        return LoginResult.UserNotFound
    }

    if (password != "12345") {
        return LoginResult.InvalidPassword
    }

    return LoginResult.Success(userName)
}
```

Обработка:

```kotlin
when (val result = login("Alex", "12345")) {

    is LoginResult.Success -> {
        println("Добро пожаловать, ${result.userName}")
    }

    LoginResult.InvalidPassword -> {
        println("Неверный пароль")
    }

    LoginResult.UserNotFound -> {
        println("Пользователь не найден")
    }

    LoginResult.AccountBlocked -> {
        println("Аккаунт заблокирован")
    }
}
```

#### `Result` или sealed class?

| `Result<T>` | `sealed class` |
|---|---|
| Успех или исключение | Любое количество явно заданных вариантов |
| Удобен для оборачивания операций, которые могут выбросить исключение | Удобен для бизнес-результатов |
| Ошибка представлена как `Throwable` | Ошибка может быть отдельным типом |
| Не описывает конкретные варианты предметной области | Позволяет явно перечислить все варианты |
| Поддерживает стандартные операции обработки результата | Требует самостоятельно описывать обработку вариантов |

#### Когда использовать исключения, а когда результат

Исключения подходят для ситуаций, когда обычный путь выполнения прерывается из-за ошибки.

`Result` удобен, когда нужно передать результат операции, которая может завершиться исключением.

`sealed class` или `sealed interface` полезны, когда у операции есть несколько ожидаемых бизнес-результатов, которые нужно явно обработать.

Например:

- ошибка чтения файла — исключение;
- результат авторизации — sealed class;
- преобразование строки в число — `toIntOrNull()` или `Result<Int>`.

### Практика: Обработка ошибок

1. Создай функцию преобразования строки в `Int` через `toInt()`.
2. Обработай `NumberFormatException` через `try / catch`.
3. Добавь `finally` и проверь, что он выполняется после успешной и неуспешной операции.
4. Создай собственное исключение для отрицательного баланса.
5. Напиши функцию, которая выбрасывает `IllegalArgumentException`, если входной аргумент некорректен.
6. Создай nullable-переменную и безопасно получи её длину через `?.`.
7. Используй Elvis operator для значения по умолчанию.
8. Покажи разницу между `!!` и безопасным доступом.
9. Используй `runCatching` для преобразования строки в число.
10. Обработай `Result` через `onSuccess` и `onFailure`.
11. Создай `sealed class` для представления результата авторизации.
12. Объясни, почему не следует без необходимости перехватывать `Throwable`.

#### Мини-шпаргалка: Обработка ошибок

- **Блок с возможной ошибкой** — `try { ... }`
- **Перехват ошибки** — `catch (e: Exception) { ... }`
- **Код, который выполнится всегда** — `finally { ... }`
- **Безопасный доступ** — `value?.property`
- **Значение по умолчанию** — `value ?: default`
- **Безопасное преобразование** — `text.toIntOrNull()`
- **Результат операции** — `Result<T>`

> [!WARNING]
> **Частая ошибка:** перехватывать `Throwable` или `Exception` слишком рано. Перехватывайте только те ошибки, которые действительно можете обработать.

## 9. Основы алгоритмов {#osnovy-algoritmov}

Алгоритм — последовательность действий, которая приводит к решению определённой задачи.

В программировании алгоритмы используются постоянно:

- поиск пользователя;
- сортировка товаров;
- фильтрация списка;
- вычисление статистики;
- преобразование данных;
- сравнение элементов;
- поиск дубликатов.

Важно не просто написать код, который работает, а понимать, сколько ресурсов он потребляет и как ведёт себя при увеличении объёма данных.

В этом разделе рассматриваются базовые операции над массивами и строками, линейный поиск, сортировка и временная сложность.

> **Ключевая идея:** сначала напишите понятный алгоритм, затем оцените его сложность и улучшайте только там, где это действительно нужно.

### 9.1. Линейный поиск {#lineynyy-poisk}

Линейный поиск (*Linear Search*) — алгоритм, который последовательно проверяет каждый элемент коллекции, пока не найдёт нужный или не достигнет конца.

Предположим, у нас есть массив:

```kotlin
val numbers = intArrayOf(10, 20, 30, 40, 50)
```

Нужно найти число `30`.

Принцип работы:

1. Проверить первый элемент.
2. Если он не совпадает с искомым, перейти к следующему.
3. Повторять, пока элемент не будет найден.
4. Если конец массива достигнут, значит, элемента нет.

#### Реализация

```kotlin
fun linearSearch(
    numbers: IntArray,
    target: Int
): Int {

    for (index in numbers.indices) {
        if (numbers[index] == target) {
            return index
        }
    }

    return -1
}
```

Использование:

```kotlin
val numbers = intArrayOf(10, 20, 30, 40, 50)

val result = linearSearch(numbers, 30)

println(result) // 2
```

Если элемент не найден, функция вернёт `-1`.

#### Почему именно `-1`

Индексы массива начинаются с нуля, поэтому отрицательное значение не может быть корректным индексом.

Это распространённый способ обозначить отсутствие результата.

Другой вариант — возвращать `Int?`, используя `null`:

```kotlin
fun linearSearch(
    numbers: IntArray,
    target: Int
): Int? {

    for (index in numbers.indices) {
        if (numbers[index] == target) {
            return index
        }
    }

    return null
}
```

Так результат отсутствия выражается через nullable-тип.

#### Сложность линейного поиска

Предположим:

- в массиве один элемент;
- в массиве 100 элементов;
- в массиве 1 000 000 элементов.

В худшем случае алгоритм должен проверить все элементы.

Если количество элементов равно `n`, количество сравнений пропорционально `n`.

Временная сложность:

**O(n)**

Линейный поиск подходит для небольших коллекций, а также для данных, которые не отсортированы и не имеют дополнительной структуры поиска.

### 9.2. Базовые операции над массивами и строками {#bazovye-operatsii-nad-massivami-i-strokami}

#### Доступ к элементу массива

```kotlin
val numbers = intArrayOf(10, 20, 30)

val first = numbers[0]
```

Доступ по индексу выполняется за постоянное время.

В обозначениях Big O:

**O(1)**

Это означает, что количество операций не зависит от размера массива.

#### Поиск элемента

```kotlin
val numbers = listOf(10, 20, 30, 40)

val contains = numbers.contains(30)
```

В обычном списке поиск элемента требует последовательной проверки элементов.

Временная сложность в общем случае:

**O(n)**

#### Добавление и удаление элементов

Для `MutableList`, который по умолчанию обычно реализуется как динамический массив (`ArrayList`) на JVM:

- добавление в конец обычно выполняется за амортизированное O(1);
- доступ по индексу — O(1);
- вставка или удаление в середине обычно требуют сдвига элементов — O(n).

Эти оценки относятся к типичной реализации динамического массива, а не являются универсальным контрактом для каждой возможной реализации `MutableList`.

#### Обход массива: Основы алгоритмов

```kotlin
val numbers = intArrayOf(1, 2, 3, 4, 5)

for (number in numbers) {
    println(number)
}
```

Если в массиве `n` элементов, цикл выполнится `n` раз.

Сложность:

**O(n)**

#### Простое преобразование массива

```kotlin
val numbers = listOf(1, 2, 3, 4)

val doubled = numbers.map { it * 2 }

println(doubled) // [2, 4, 6, 8]
```

Каждый элемент обрабатывается один раз.

Временная сложность:

**O(n)**

#### Работа со строками

Строки в Kotlin неизменяемые.

```kotlin
val text = "Kotlin"

val upper = text.uppercase()
val reversed = text.reversed()
val contains = text.contains("lin")
```

Каждая операция возвращает результат, не изменяя исходную строку.

Повторная конкатенация строк в цикле может приводить к созданию большого количества промежуточных объектов:

```kotlin
var result = ""

for (i in 1..100) {
    result += i
}
```

Для последовательного построения длинной строки лучше использовать `StringBuilder`:

```kotlin
val builder = StringBuilder()

for (i in 1..100) {
    builder.append(i)
}

val result = builder.toString()
```

`StringBuilder` особенно полезен, когда строка формируется большим количеством операций добавления.

### 9.3. Сортировка и её назначение {#sortirovka-i-ee-naznachenie}

Сортировка — упорядочивание элементов по определённому критерию.

Примеры:

- числа по возрастанию;
- товары по цене;
- пользователи по имени;
- задачи по дате создания;
- результаты тестов по количеству баллов.

#### Сортировка чисел

```kotlin
val numbers = listOf(5, 2, 8, 1, 3)

val sorted = numbers.sorted()

println(sorted) // [1, 2, 3, 5, 8]
```

По убыванию:

```kotlin
val sortedDescending = numbers.sortedDescending()
```

#### Сортировка изменяемого списка

```kotlin
val numbers = mutableListOf(5, 2, 8, 1, 3)

numbers.sort()

println(numbers) // [1, 2, 3, 5, 8]
```

Разница:

- `sorted()` возвращает новую отсортированную коллекцию;
- `sort()` сортирует mutable-коллекцию на месте.

#### Сортировка объектов

```kotlin
data class User(
    val name: String,
    val age: Int
)

val users = listOf(
    User("Alex", 25),
    User("Maria", 20),
    User("John", 30)
)
```

По возрасту:

```kotlin
val sortedByAge = users.sortedBy { user ->
    user.age
}
```

По имени:

```kotlin
val sortedByName = users.sortedBy { user ->
    user.name
}
```

По убыванию возраста:

```kotlin
val sortedByAgeDescending = users.sortedByDescending {
    it.age
}
```

#### Зачем сортировать данные

Сортировка нужна не только для отображения.

Она помогает:

- сделать результаты предсказуемыми;
- упростить сравнение элементов;
- подготовить данные для некоторых алгоритмов поиска;
- группировать и анализировать информацию;
- формировать удобные пользовательские списки.

#### Сложность сортировки

Для распространённых сравнительных алгоритмов сортировки типичная временная сложность составляет:

**O(n log n)**

Это означает, что время растёт быстрее линейно, но значительно медленнее, чем у квадратичного алгоритма при больших объёмах данных.

Конкретная сложность зависит от алгоритма и входных данных.

Не нужно самостоятельно реализовывать сортировку в обычном прикладном коде, если стандартная библиотека уже предоставляет подходящий метод.

Но важно понимать, какие ресурсы требуются для сортировки.

### 9.4. Вложенные циклы и оценка количества операций {#vlozhennye-tsikly-i-otsenka-kolichestva-operatsiy}

Вложенные циклы часто используются для сравнения элементов или обработки двумерных структур.

```kotlin
val numbers = listOf(1, 2, 3)

for (first in numbers) {
    for (second in numbers) {
        println("$first, $second")
    }
}
```

Если в коллекции три элемента, внутренний код выполнится девять раз.

Почему?

- для первого элемента внешний цикл — 3 внутренних итерации;
- для второго элемента — ещё 3;
- для третьего — ещё 3.

Итого:

`3 * 3 = 9`.

Для массива из `n` элементов:

`n * n = n²`.

#### Пример сравнения каждой пары

```kotlin
fun printPairs(numbers: List<Int>) {
    for (first in numbers) {
        for (second in numbers) {
            println("$first and $second")
        }
    }
}
```

Количество комбинаций растёт квадратично.

Если увеличить размер входных данных в два раза, количество операций в таком алгоритме увеличится примерно в четыре раза.

#### Вложенные циклы не всегда означают O(n²)

Важно учитывать реальное количество итераций.

Например:

```kotlin
for (i in 1..n) {
    for (j in 1..10) {
        println("$i $j")
    }
}
```

Внутренний цикл выполняется всегда 10 раз, независимо от `n`.

Общее количество операций:

`n * 10`.

Постоянный множитель в Big O не учитывается.

Сложность:

**O(n)**

Поэтому при оценке алгоритма важно анализировать количество операций, а не просто считать вложенность циклов.

### 9.5. Понятие временной сложности {#ponyatie-vremennoy-slozhnosti}

Временная сложность — оценка того, как изменяется количество вычислений алгоритма при увеличении входных данных.

Обычно размер входа обозначается буквой `n`.

Мы не пытаемся измерить время выполнения в миллисекундах.

Вместо этого оцениваем, как растёт количество операций относительно размера входа.

Например:

- для 10 элементов алгоритм выполнил 10 операций;
- для 100 элементов — 100 операций;
- для 1 000 элементов — 1 000 операций.

Такое поведение соответствует линейному росту.

#### Зачем это нужно

Два алгоритма могут решать одну и ту же задачу, но иметь совершенно разную производительность.

Например, один алгоритм обходит список один раз, а другой сравнивает каждый элемент с каждым.

На маленьком наборе данных разница может быть незаметна.

На миллионах элементов — уже критична.

Временная сложность помогает оценить масштабируемость алгоритма до запуска на реальных данных.

### 9.6. Big O: O(1), O(n), O(n²) {#big-o-o-1-o-n-o-n}

Big O — обозначение порядка роста вычислительной сложности алгоритма.

Для Junior важно уверенно различать несколько базовых вариантов.

#### O(1) — постоянная сложность

Количество операций практически не зависит от количества входных данных.

Пример:

```kotlin
val numbers = listOf(10, 20, 30, 40)

val first = numbers[0]
```

Получение элемента списка по индексу имеет сложность O(1) для обычной индексируемой реализации списка.

Условно:

- 10 элементов — одна операция доступа;
- 100 элементов — одна операция доступа;
- 1 000 элементов — одна операция доступа.

#### O(n) — линейная сложность

Количество операций растёт пропорционально количеству элементов.

```kotlin
val numbers = listOf(1, 2, 3, 4, 5)

for (number in numbers) {
    println(number)
}
```

Если элементов в два раза больше, количество итераций тоже увеличится примерно в два раза.

Примеры:

- линейный поиск;
- один проход по массиву;
- фильтрация списка;
- преобразование каждого элемента через `map`.

#### O(n²) — квадратичная сложность

Количество операций растёт пропорционально квадрату размера входных данных.

```kotlin
val numbers = listOf(1, 2, 3)

for (first in numbers) {
    for (second in numbers) {
        println("$first $second")
    }
}
```

Если размер входа увеличился в два раза, количество операций увеличится примерно в четыре раза.

Примерная таблица:

| Количество элементов `n` | O(1) | O(n) | O(n²) |
|---:|---:|---:|---:|
| 10 | 1 | 10 | 100 |
| 100 | 1 | 100 | 10 000 |
| 1 000 | 1 | 1 000 | 1 000 000 |
| 10 000 | 1 | 10 000 | 100 000 000 |

Таблица показывает, почему квадратичные алгоритмы могут стать проблемой на больших объёмах данных.

#### Ещё два обозначения, которые полезно знать

Хотя на этом уровне достаточно сосредоточиться на O(1), O(n) и O(n²), часто встречаются ещё два варианта.

**O(log n)** — логарифмическая сложность.

Пример — бинарный поиск в отсортированном массиве.

На каждом шаге область поиска уменьшается примерно вдвое.

**O(n log n)** — сложность, характерная для многих эффективных алгоритмов сортировки.

#### Почему Big O игнорирует константы

Представим два алгоритма:

```kotlin
fun first(numbers: List<Int>) {
    for (number in numbers) {
        println(number)
    }
}

fun second(numbers: List<Int>) {
    for (number in numbers) {
        println(number)
    }

    for (number in numbers) {
        println(number)
    }
}
```

Первый алгоритм обходит список один раз.

Второй — два раза.

Формально:

- первый: `O(n)`;
- второй: `O(2n)`.

Но в Big O постоянный множитель игнорируется.

Оба алгоритма имеют сложность:

**O(n)**

Это не означает, что они работают одинаково быстро. Это означает, что их скорость роста относительно размера входных данных относится к одному классу.

#### Сложность по нескольким последовательным операциям

```kotlin
fun process(numbers: List<Int>) {
    for (number in numbers) {
        println(number)
    }

    for (number in numbers) {
        println(number * 2)
    }
}
```

Здесь:

- первый цикл — O(n);
- второй цикл — O(n);
- общее количество операций — O(2n);
- итоговая сложность — O(n).

Если же циклы вложены, ситуация будет другой:

```kotlin
fun process(numbers: List<Int>) {
    for (first in numbers) {
        for (second in numbers) {
            println("$first $second")
        }
    }
}
```

Здесь сложность — O(n²).

### 9.7. Простые задачи на преобразование коллекций {#prostye-zadachi-na-preobrazovanie-kollektsiy}

В прикладной разработке очень часто встречается задача преобразовать одну коллекцию в другую.

Для этого стандартная библиотека Kotlin предоставляет `map`, `filter` и другие функции.

#### Фильтрация

Задача: получить только пользователей старше 18 лет.

```kotlin
data class User(
    val name: String,
    val age: Int
)

val users = listOf(
    User("Alex", 25),
    User("Maria", 17),
    User("John", 30),
    User("Peter", 16)
)

val adults = users.filter { user ->
    user.age >= 18
}
```

#### Преобразование

Задача: получить только имена пользователей.

```kotlin
val names = users.map { user ->
    user.name
}
```

#### Комбинация фильтрации и преобразования

Задача: получить имена только совершеннолетних пользователей.

```kotlin
val adultNames = users
    .filter { it.age >= 18 }
    .map { it.name }
```

#### Поиск

Задача: найти пользователя с именем `Maria`.

```kotlin
val user = users.find {
    it.name == "Maria"
}
```

Если пользователя нет, результатом будет `null`.

#### Проверка условий

Есть ли среди пользователей несовершеннолетние?

```kotlin
val hasMinors = users.any {
    it.age < 18
}
```

Все ли пользователи совершеннолетние?

```kotlin
val allAdults = users.all {
    it.age >= 18
}
```

#### Подсчёт элементов

```kotlin
val adultCount = users.count {
    it.age >= 18
}
```

#### Получение уникальных значений

```kotlin
val ages = users
    .map { it.age }
    .distinct()
```

#### Почему это важно: Основы алгоритмов

Подобные операции постоянно встречаются при разработке:

- экранов со списками;
- фильтров;
- поисковых интерфейсов;
- обработки результатов API;
- статистики;
- аналитики;
- бизнес-логики.

При этом необходимо понимать, что большинство операций `Iterable`, например `map` и `filter`, создают новые коллекции и выполняют обработку сразу.

Если операций много, важно учитывать не только время, но и количество промежуточных коллекций, которые создаются в памяти.

Для более сложных сценариев в Kotlin существуют `Sequence`, но это уже отдельная тема.

### Практика: Основы алгоритмов

1. Реализуй линейный поиск элемента в массиве.
2. Измени функцию поиска так, чтобы она возвращала `null`, если элемент отсутствует.
3. Найди максимальное число в массиве, не используя готовую функцию `maxOrNull()`.
4. Подсчитай количество чётных чисел в коллекции.
5. Отсортируй список чисел по возрастанию и убыванию.
6. Отсортируй список пользователей по возрасту.
7. Оцени количество операций в двух вложенных циклах размером `n`.
8. Объясни, почему два последовательных цикла имеют O(n), а два вложенных — обычно O(n²).
9. Отфильтруй пользователей старше 18 лет.
10. Преобразуй список пользователей в список имён.
11. Найди первого пользователя, удовлетворяющего условию.
12. Проверь, что все элементы списка положительные.
13. Объясни разницу между `O(1)`, `O(n)` и `O(n²)` на собственных примерах.

#### Дополнительная практическая задача

Есть список результатов прохождения тестов:

```kotlin

    val score: Int
```

3. Отсортировать результат по убыванию баллов.
4. Найти пользователя с максимальным баллом.
5. Посчитать средний балл всех участников.
6. Определить, есть ли участник с результатом ниже 50.

Постарайся решить задачу сначала обычными циклами, а затем функциями стандартной библиотеки Kotlin.

Сравни читаемость обоих вариантов.

- функции для разделения логики;
- классы и `enum` для моделирования предметной области;
- коллекции для хранения данных;
- `filter`, `map`, `find` и `sortedBy` для обработки;
- `require` или собственные исключения для проверки входных данных.

**Критерий завершения:** программа должна корректно работать с пустым списком, несколькими элементами, отсутствующими идентификаторами и некорректными входными данными.
