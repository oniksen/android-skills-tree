ПРАВИЛА ФОРМАТИРОВАНИЯ УЧЕБНЫХ МАТЕРИАЛОВ
==========================================

Файлы лежат в content/study-materials/<уровень>/<id>.md
Уровни: junior, middle, strong-middle, senior.
id файла = id материала. Он привязывается в src/data/categories.ts или
src/data/skills/<grade>.ts через поле studyMaterial: "<id>".

Файл — обычный Markdown (GFM). HTML-теги в файле запрещены: всё оформление
делает рендерер (реестр блоков src/features/study/model/study-blocks.ts,
разбор src/features/study/model/parse-study-document.ts).

Любая открытая конструкция должна быть закрыта: фенс кода и директива
:::cards; у таблицы должна быть строка-разделитель. Что будет, если
правило нарушено — раздел 17.


1. СТРУКТУРА ФАЙЛА
------------------

# Заголовок страницы

**Уровень:** Junior
**Категория:** Основы программирования
**Язык:** Kotlin
**Кратко:** Одно предложение для вводного абзаца страницы.
**Футер:** Необязательная подпись внизу страницы.

## 1. Первый раздел

Текст раздела.

### 1.1. Подраздел

Текст подраздела.

## 2. Второй раздел

...

## Источники и документация

### Официальная документация

- [Название](https://example.com/page)


2. ЗАГОЛОВКИ
------------

Уровень      Что задаёт        Как выглядит в HTML
H1 (#)       заголовок         h1.study-title в header.study-hero
                               (единственный H1 в файле)
H2 (##)      раздел            section#sec-N.study-section >
                               h2#sec-N-title.study-section-title
                               + nav.study-nav > a.study-nav-link
H3 (###)     подраздел         h3.study-subtitle
H4 (####)    мелкий заголовок  h4.study-subtitle.study-subtitle--minor
H5 (#####)   то же, что H4     h4.study-subtitle.study-subtitle--minor
H6 (######)  то же, что H4     h4.study-subtitle.study-subtitle--minor

H1 — ровно один, только заголовок страницы.
H2 — раздел: попадает в авто-навигацию и получает якорь sec-N.
H3 — подраздел внутри раздела. Глубже H4 не уходите.
H5/H6 рендерятся как H4: визуально мельче уже некуда.

Не пишите "## Содержание": навигация строится автоматически. Разделы
"Содержание", "Оглавление" и "Contents" (ровно эти слова) рендерер
пропускает.

В заголовках можно использовать `код` и **жирный** — они отрендерятся.
В навигацию заголовок попадает очищенным текстом.


3. МЕТАДАННЫЕ
-------------

Метаданные — строки сразу под H1, каждая на своей строке:

**Уровень:** Junior
**Категория:** Основы программирования
**Язык:** Kotlin
**Кратко:** ...
**Футер:** ...

Читаются только строки между H1 и первым H2; ниже в файле такие строки
метаданными уже не считаются. Обязательных полей нет: если "Уровень"
не указан, подставится уровень из папки материала.

Над заголовком — eyebrow: "Категория · Уровень"; если категории нет, то
"Язык · Уровень". Если "Кратко" нет, лид соберётся сам; "Футер" тоже
необязателен — иначе подпись соберётся из уровня и языка.


4. ТЕКСТ И ИНЛАЙН
-----------------

- Абзацы разделяются пустой строкой.
- `код` — инлайн-код в обратных кавычках.
- **жирный**, *курсив*.
- [Текст ссылки](https://example.com) — внешние ссылки открываются в новой
  вкладке автоматически.
- > цитата — блок-заметка (см. раздел 9).
- Переносы строк внутри абзаца не нужны: пишите абзац одной строкой.
- Горизонтальные линии (---) между разделами не нужны: разделы и так
  оформляются отдельными блоками.

Картинка — отдельной строкой, не внутри предложения:

![Схема жизненного цикла](https://example.com/lifecycle.png)

Alt становится подписью под рисунком (раздел 16). Картинки без alt
запрещены (раздел 13).


5. СПИСКИ
---------

- маркированный список;
- второй пункт.

1. нумерованный список;
2. второй пункт.

Маркированный список рендерится как ul.study-list, нумерованный — как
ol.study-list. Вложенный список — с отступом в 2 пробела; глубже двух
уровней не уходите: на телефоне это плохо читается.

Список задач GFM — отдельный блок, см. раздел 6.


6. ЧЕК-ЛИСТ (САМОПРОВЕРКА)
--------------------------

Список задач GFM рендерится отдельным блоком-чеклистом:

- [ ] Первый пункт самопроверки.
- [ ] Второй пункт.
- [x] Уже отмеченный пункт.

Разметка: ul.study-checklist > li.study-check-item >
input[type="checkbox"][disabled] (у [x] ещё и checked).

Чекбоксы визуальные: состояние не сохраняется между визитами.


7. ТАБЛИЦЫ
----------

Таблица GFM: строка заголовка, строка-разделитель, строки.

| Тип | Размер | Назначение |
|---|---|---|
| `Int` | 32 бита | Основной целочисленный тип |
| `Long` | 64 бита | Большие целые числа |

Таблица оборачивается в скролл-блок:
div.study-table-wrap[role="group"][aria-label="Таблица"][tabindex="0"]
> table.study-table.

- Строка заголовка и строка-разделитель обязательны: без разделителя
  таблица не собирается (раздел 17).
- Выравнивание колонок разрешено (:---, :---:, ---:) и приходит как
  style="text-align:..." на ячейках th и td.
- Не больше 4 колонок: на телефоне таблица скроллится внутри блока.
- Не оставляйте пустых ячеек.
- В ячейках можно использовать `код`, **жирный** и ссылки.
- Блоки (код, списки, цитаты, картинки) в ячейку вставлять нельзя.


8. КОД
------

Блок кода — только с языком после открывающих обратных кавычек:

```kotlin
val name = "Alex"
```

Языки: kotlin, xml, java, json, bash, text, sql, gradle, yaml.
Других языков нет: блок с неизвестным языком теряет подсветку.

- Фенс закрывается тем же символом — обратными кавычками или тильдами —
  и не короче открывающего. Внутри фенса ":::" — обычный текст,
  директиву он не закрывает; но не путайте читателя такими примерами.
- Без языка блок рендерится без подсветки (code.hljs), поэтому фенс
  без языка ("голые" обратные кавычки) не используйте.
- Длина строки в примере — до 80 символов, длинные примеры сокращайте.
- Инлайн-код внутри блока кода не форматируется.
- В заметке блок кода тоже работает: каждая строка цитаты начинается
  с "> " (раздел 9).


9. ЗАМЕТКИ И ПРЕДУПРЕЖДЕНИЯ
---------------------------

Обычная цитата становится заметкой:

> **Запомнить:** выбирайте `val` по умолчанию.

Предупреждение — цитата с маркером [!WARNING] или [!CAUTION]
в первой строке:

> [!WARNING]
> Вызов `lateinit`-свойства до инициализации бросает
> `UninitializedPropertyAccessException`.

Каждый алерт — отдельный блок цитаты, между алертами пустая строка:

> [!NOTE]
> Обычная заметка.

> [!TIP]
> Подсказка.

Варианты:

[!NOTE], [!TIP], [!IMPORTANT]  div.study-note
[!WARNING], [!CAUTION]         div.study-note.study-note--warn

Правила:

- Маркер стоит в первой строке своей цитаты и занимает строку целиком:
  "[!NOTE] Текст" маркером не считается и останется видимым текстом.
- Если маркер оказался ниже первой строки, он начинает новую заметку:
  текст до него — одна заметка, после — другая (поведение v2). Лучше так
  не писать и ставить маркер сразу.
- В заметке можно списки и блоки кода, но каждая строка цитаты
  начинается с "> ", включая пустые строки (там просто ">").
- :::cards внутри заметки не работает — см. разделы 10 и 13.
- Устаревший маркер "⚠" в первой строке тоже даёт warn-вариант;
  в новых материалах используйте [!WARNING] / [!CAUTION].


10. КАРТОЧКИ
------------

Сетка мини-карточек — директива :::cards. Внутри — только список:

:::cards
- **Имя** — понятное имя описывает назначение: `userName`, а не `x`.
- **Значение** — можно вычислить или получить от пользователя.
- **Тип** — Kotlin знает тип переменной.
:::

Разметка: div.study-cards > div.study-card > p.study-card-title + текст.

Правила:

- Открывающая строка ровно ":::cards", закрывающая ровно ":::";
  обе — с начала строки, без отступа.
- Только верхний уровень секции: в заметке (внутри ">") карточки
  не работают, маркеры останутся видимым текстом.
- 2–6 пунктов — правило для автора, код его не проверяет.
- Формат пункта: - **Заголовок** — текст. Без **Заголовка** карточка
  выйдет без заголовка.
- Одна карточка — одна строка: переносы склеиваются в один абзац.
- Вложенные списки не поддерживаются: строка "- ..." с отступом станет
  ещё одной карточкой.
- Пустая директива ничего не выводит: пустая сетка не создаётся.


11. ИСТОЧНИКИ
-------------

Последний раздел называется "Источники и документация". Режим пилюль
включает слово "источник" в заголовке H2 — не используйте его в названиях
обычных разделов.

Внутри — группы через H3 и списки ссылок:

## Источники и документация

### Официальная документация

- [Properties](https://kotlinlang.org/docs/properties.html)
- [Basic syntax](https://kotlinlang.org/docs/basic-syntax.html)

### Статьи

- [Название статьи](https://example.com/article)

Разметка: ul.study-pills > li > a.study-pill.

Каждый маркированный список в разделе источников рендерится
горизонтальными пилюлями, а каждая ссылка получает класс пилюли, даже
внутри абзаца. Поэтому кроме ссылок в пункте ничего не пишите, а подпись
ссылки держите короткой. Нумерованный список остаётся обычным
ol.study-list, но ссылки в нём всё равно пилюли.


12. ИТОГОВАЯ САМОПРОВЕРКА
-------------------------

Последний содержательный раздел (перед источниками):

## Итоговая самопроверка категории

- [ ] Пункт 1.
- [ ] Пункт 2.


13. ЗАПРЕТЫ
-----------

- HTML-теги (<div>, <table>, <code>, <strong>, <br>) — запрещены.
- Картинки без alt — запрещены. Картинка с alt рендерится с подписью.
- Картинка в одном абзаце с текстом — запрещена: получится невалидный
  HTML (раздел 17).
- :::cards внутри заметки — запрещено.
- Два алерта в одной цитате подряд без пустой строки — так не пишите:
  рендерер их разделит, но исходник читается плохо. Каждый алерт —
  отдельным блоком "> " с пустой строкой между блоками.
- Незакрытый фенс кода, незакрытая директива :::cards, таблица без
  строки-разделителя — запрещены (раздел 17).
- Не используйте несколько H1: включится устаревший режим разбора.
- Не пишите свою навигацию и своё оглавление.
- Не дублируйте разделы: они попадут в навигацию дважды.


14. ОБЪЁМ И СОДЕРЖАНИЕ
----------------------

- Не меньше 700 слов чистой информации на тему (без кода и разметки).
- Каждая тема покрывает все подтемы навыка из src/data/skills/<grade>.ts.
- Нужны конкретные примеры, реальные случаи и частые ошибки.
- Один раздел — одна мысль; подразделы короче 3–4 абзацев.


15. ПРОВЕРКА ПЕРЕД КОММИТОМ
---------------------------

- H1 один, метаданные под ним.
- Разделы — H2, подразделы — H3, глубже — H4.
- Нет HTML-тегов и "голых" блоков кода.
- Таблицы с заголовком и не шире 4 колонок.
- :::cards закрыт и содержит 2–6 пунктов.
- Источники — отдельным последним разделом.
- Прогнать:

  npm run generate:materials
  npm run lint
  npm run typecheck
  npm test
  npm run build

npm test включает проверку валидности HTML (html-validate): невалидная
разметка валит тест материалов.

17. ЕСЛИ ЧТО-ТО НЕ ЗАКРЫТО
--------------------------

Ситуация                         Что увидит читатель
:::cards без закрывающего :::    открывашка выброшена, тело остаётся
                                 обычным Markdown: карточек нет, но и
                                 сырой маркер :::cards не показывается
:::cards внутри заметки          директивы нет: строки :::cards и :::
                                 останутся видимым текстом заметки
фенс кода без закрытия           всё до конца файла — код; следующие
                                 H2 уже не станут разделами
::: без :::cards                 обычный текст, ::: видно на странице
таблица без строки-разделителя   абзац с символами |, а не таблица
картинка в абзаце с текстом      невалидный HTML: html-validate валит
                                 npm test
алерт ниже первой строки цитаты  начинает новую заметку (текст до
                                 него остаётся в предыдущей)
