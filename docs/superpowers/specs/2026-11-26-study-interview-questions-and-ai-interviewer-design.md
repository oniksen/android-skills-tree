# Дизайн: вынос вопросов для собеседования в отдельные файлы и ИИ-собеседующий в квизе

- Дата: 2026-11-26
- Статус: черновик для реализации
- Ветка: создать от `develop`: `feat/study-interview-questions-and-ai-interviewer`

## 0. Ветка и процесс

1. Создать ветку от `develop`:
   - `git checkout develop && git pull`
   - `git checkout -b feat/study-interview-questions-and-ai-interviewer`
2. Во время выполнения **каждый этап** отмечается в агентном TODO-списке сразу после завершения этапа, а не после завершения всей работы.
3. Задачи выполняются **суб-агентами** (отдельные сессии/агенты на этап). Каждый суб-агент получает только свой этап и не меняет исходную модель/данные вне своего этапа.
4. Исходная модель данных (`QuizQuestion`, `StudySectionBlock`, `StudyDocument` и т.д.) **не меняется** без явного согласования; расширения только через новые опциональные поля/новые файлы.
5. После каждого этапа: `npm run lint`, `npm run typecheck`, `npm test` (где применимо).

## 1. Цель

- Вынести все `:::qa`-блоки из учебных материалов в отдельные файлы по грейдам.
- Сохранить отображение Q&A на странице study через метод дополнения в маппере Markdown → HTML.
- Сделать квиз полноценным ИИ-собеседующим, использующим вопросы из этих файлов.
- Сохранить существующую функцию hover-подсказки с количеством вопросов по навыку.

## 2. Точки отказа и меры

1. **Потеря Q&A при удалении из Markdown**  
   Мера: сначала создать внешние файлы и проверить количество вопросов; только потом удалять блоки.

2. **Неверный маппинг H2 → skill**  
   Мера: маппить по порядковому номеру major-секции к skill категории по `sortOrder`; добавить тест на полное совпадение количества.

3. **Сломанные golden-фикстуры**  
   Мера: регенерировать через `npm run study:golden`, затем проверить `study-html-validity`.

4. **Счётчик вопросов в `QuizInfoIcon` станет 0**  
   Мера: подключить внешние файлы в `allQuizQuestions` до удаления старых данных.

5. **Потеря ответов для study-страницы**  
   Мера: внешние файлы хранят `question` и `answer`; маппер использует оба.

6. **Дублирование вопросов**  
   Мера: после переноса удалить `:::qa` из Markdown; маппер добавляет блок автоматически.

7. **Отсутствие данных для будущих грейдов**  
   Мера: создать пустые файлы `middle.ts`, `strong-middle.ts`, `senior.ts`.

## 3. Структура файлов

```
src/data/study-interview-questions/
  index.ts
  junior.ts
  middle.ts
  strong-middle.ts
  senior.ts
```

Каждый файл экспортирует массив:

```ts
export interface StudyInterviewQuestion {
  question: string;
  answer: string;
}

export interface StudyInterviewTopic {
  grade: "junior" | "middle" | "strong-middle" | "senior";
  materialId: string;
  skillId: string;
  topic: string;
  questions: StudyInterviewQuestion[];
}
```
