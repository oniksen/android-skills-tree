## Зачем

После унификации пайплайна остались три класса проблем: (1) маркеры алертов, стоящие не в
первой строке цитаты, печатались текстом; (2) часть тестов давала ложное покрытие; (3) маппинг
Markdown не был измерен, а гайд автора описывал пайплайн v1.

## Инварианты, которые теперь защищены тестами

- побайтовый golden-эталон HTML (`components/__fixtures__/study-render/*.html`) — менять
  эталон нельзя, любое расхождение считается регрессией;
- процессор собирается ровно один раз на модуль (мок `unified`);
- `react-markdown` не вызывается в рантайме;
- опасные протоколы ссылок вырезаются, как в react-markdown;
- каждый kind реестра встречается в статической разметке и рендерится заявленным тегом;
- язык кода в гайде совпадает с набором грамматик;
- примеры из гайда проходят html-validate.

## Отклонения и ограничения

- Лимит кэша 128 (в проекте было 50): при 50 большой материал промахивался мимо кэша
  (146.7 ms против 33.3 ms). Цена — ~10.5 MB heap на 96 записей (≈112 KB/запись), до ~14 MB
  при 128; сериализованный JSON в 2.8 раза меньше реального heap.
- FIFO, не LRU: при росте контента свыше 128 ключей промахи вернутся. Следующий шаг — LRU
  или бюджет по размеру.
- `react-markdown` остаётся в клиентском графе только ради `defaultUrlTransform`;
  при отказе от зависимости функцию придётся скопировать.
- `post()` скопирован из react-markdown: при мажорном обновлении нужна ручная сверка,
  дрейф поймает golden-тест.
- Картинка в одном абзаце с текстом по-прежнему даёт невалидный HTML — теперь это ловится
  тестом, в гайде запрещено.
- `:::cards` внутри `>`-заметки не поддерживается (зафиксировано в гайде и разделе 17).
- Секция «Итоговый список официальной документации Kotlin» не помечена `sources`, потому что
  `SOURCES_TITLE` ищет слово «источник»: контентный дрейф, не баг кода.
